# 제품 예제와 선택 시험의 분리

현재 하네스는 공통 실행·계약·검증 코드를 제공한다. 특정 제품의 요구사항·화면·구현·시나리오와 선택 실제 모델 시험을 제품 작업의 기본 입력이나 설치 의존성으로 사용하지 않는다. KMP 필수 기준과 제품별 DB 결정 절차는 공통 계약이며 예제 제품의 세부 결정과 구분한다.

## 현재 소스와 보존 경계

이 변경 이후의 현재 Git tree와 그 소스로 만든 새 설치물에서 제품 예제 문서, Ktor 메모 fixture, 앱별 시험 도구·시나리오, 전용 trial worker·dashboard fixture와 메모 시험 도구·전용 테스트를 제외한다. 공통 단위 테스트는 제품과 무관한 임시 합성 입력을 사용한다. 적용 제품은 자기 원본·설정·시나리오·검증 근거를 자기 프로젝트에 보관한다.

기존 파일은 원래 로컬 경로에 그대로 보존하고 Git index에서만 제거한다. 별도 companion을 준비할 때는 원본을 복사하고 해시를 확인하며 원본을 삭제·이동하지 않는다. 과거 Git 이력과 기존 릴리스 태그도 보존한다. 따라서 일반 full clone에 과거 예제의 역사 객체가 내려오지 않는다고 보장하지 않는다. 이미 설치한 버전을 자동 변경하거나 과거 배포 내용을 소급 수정하지 않는다.

## 별도 로컬 companion

companion은 하네스 저장소에서 제외한 `verification/examples-companion/` 아래 별도 로컬 Git 저장소로 준비한다. 새 GitHub 저장소·원격을 만들거나 공개하지 않는다. 이 로컬 경로는 제품 설치 경로가 아니며 설치·업데이트가 companion을 자동 탐색하거나 복사하지 않는다.

companion의 분리 구조는 `docs/`, `tools/`, `harness/`의 전용 legacy trial worker, `tests/test_memo_trial_contract.py`, `DEPENDENCIES.json`과 자체 README로 구성한다. 이 경로들은 companion 내부 경로이며 하네스 설치물의 제공 파일을 뜻하지 않는다. `DEPENDENCIES.json`과 README에 실제로 선택한 하네스 source/ref와 시험 의존성을 기록한 뒤 별도로 실행한다. 구체 명령·호환 버전은 companion에서 확정하며 이 문서는 실행 가능한 미확정 명령을 제시하지 않는다.

제품 작업에서 companion이나 과거 예제를 자동 로드하지 않는다. 별도 시험을 요청한 경우에만 해당 범위·하네스 source/ref·실행 환경을 확인한다. 특정 예제의 DB·플랫폼·정책·화면을 새 제품의 요구사항으로 승계하지 않는다.

## 시험과 완료 근거

실제 시험 허가 원문과 합성 fixture를 계보에서 구분하고 원문을 가짜 승인으로 대체하지 않는다. 구현·수리 전 독립 요구사항 QA, 필요한 실제 모델·빌드·HTTP·시각 검증과 현재 입력 연결을 유지한다. 예제 분리는 검사나 제품별 필수 검증을 생략할 권한이 아니다. UI 비해당 여부는 [공통 계약](ui-applicability.md)으로 별도 판단한다.

개별 실제 모델 실행 기록·원문·캡처·로그와 검증 원본은 로컬에 보존하고 하네스 PR에 포함하지 않는다. 시험 저장소와 원문도 업로드하지 않는다. 합성 회귀 성공, 실제 모델 실행 결과, 제품 인수와 공식 보호 검증은 구분한다. 한 시험의 성공으로 제품 전체나 다른 요청을 PASS 처리하지 않으며 미관측 원문 ID·사용량은 UNKNOWN/pending으로 유지한다.

과거 문서 인계·연결 시험의 완료 요약은 해당 당시 범위의 사실이다. 원본 경로를 보존하더라도 새 체크아웃에서 그 실행 전체를 재현할 수 있다고 주장하지 않는다. 새로운 제품의 완료 판단은 해당 프로젝트의 현재 입력·산출물·독립 검토 근거를 사용한다.
