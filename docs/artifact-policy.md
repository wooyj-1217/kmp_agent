# 현재 맥락·작업 이력·검증 증거 관리

기록이 늘어도 작업 시작에 읽는 양은 제한한다. 현재 기준은 갱신하고, 변경 이유와 결정은 작업 기록에, 변경 전후는 Git에 둔다. 제품 문서·원본 로그는 해당 프로젝트에 보관하며 공통 저장소로 자동 전송하지 않는다.

## 기록의 역할과 위치

- 현재 명세: 프로젝트가 지정한 요구·디자인·API 계약의 현재 유효한 기준. 대체된 기준을 본문에 누적하지 않는다.
- 시작 맥락: 현재 결정·구현 사실·미해결·주의사항과 관련 경로만 둔다. 과거 설치·테스트 수치·전체 연혁은 작업 이력으로 분리한다. 공통 저장소의 진입점은 AGENTS.md이며 프로젝트별 맥락 경로를 강제하지 않는다.
- 작업 이력: [템플릿](work-items/TEMPLATE.md)을 사용해 `docs/work-items/YYYY/YYYY-MM-DD-주제.md` 한 파일에서 요청·주요 결정·결과·검증·PR/커밋/릴리스를 연결한다. 기존 상세 작업 기록이 있으면 재사용하고 같은 정보를 복제하지 않는다. 파일명은 검색용이며 하네스 ID가 아니다.
- 변경 전후: Git diff와 한국어 커밋 메시지에 이유·영향·실제 검증·작업 기록을 남긴다. 에이전트/제품별 별도 커밋 분류나 새로운 ID 체계를 강제하지 않는다.
- 검증 원본: 관련 프로젝트의 기존 로컬 경로에서 보존하고 필요할 때 [로컬 검증 절차](local-verification.md)에 따라 확인한다. 원본 증거는 Git·PR·원격 보관소에 업로드하거나 삭제·이동하지 않는다.

현재 문서에서 과거 기록을 분리할 때 원래 내용·적용 시점·대체 관계를 보존하고 기존 링크·앵커는 유지하거나 명시적으로 연결한다. 문서가 미추적이면 Git에 있다는 가정으로 삭제하지 않는다. 과거 PASS를 새 코드의 PASS로 승계하지 않는다.

## 시작·진행·종료

1. 현재 진입점에서 관련 명세·코드·과거 기록만 선택한다. 작업 기록에 기준 커밋·dirty 상태·범위·유지 동작·미결정을 적는다. 기록이 있으면 재사용한다.
2. 진행 중 같은 파일의 현재 상태를 갱신한다. 사용자 확정·에이전트 제안·구현 사실을 구분하고, 중요한 변경은 대체한 결정의 경로·절 또는 커밋을 연결한다. 전체 대화·명세·로그를 복사하지 않는다.
3. 종료 시 현재 명세·맥락을 갱신하고 해결된 항목과 중복을 정리한다. 작업 기록에는 최종 결과·남은 문제·검증 대상 버전과 원본 경로를 남긴다. [맥락 정리 담당](roles/context-maintainer.md)의 실제 대조와 메인 검토를 구분한다.
4. 종료 기록의 과거 판정은 덮어쓰지 않는다. 오류 정정·추가 검증·독립 후속 변경은 날짜·이유·근거를 가진 정정 절 또는 새 기록으로 연결한다. 재개 상태·차단 이유를 완료로 표시하지 않는다.

알 수 없는 SHA·원문/실행 ID·승인·릴리스는 `UNKNOWN`으로 남기고 만들어 채우지 않는다. 실제 native TASK/run·P/D/API/CR·수집 원장은 원본이며 Markdown은 이를 대체하는 병렬 상태 DB가 아니다. 마지막 커밋의 자기 SHA를 강제하지 않으며 알려진 커밋과 `git log -- <기록 경로>`로 추적한다. 단순 오타·기계적 수정은 커밋으로 충분하면 별도 기록을 생략할 수 있다.

## 기록이 커졌을 때

연도별 작업 기록은 기본 시작 입력에서 제외하고 기능·결정·실제 ID로 `rg`와 Git 검색을 사용한다. 수동 전체 인덱스나 반복 요약 문서를 누적하지 않는다. 관련 기능 수정·기능 묶음 완료 때 현재 문서의 중복·오래된 상태·충돌·끊어진 링크를 점검한다. 큰 문서는 기능별 분리와 링크로 관리한다. 기존 자료는 점진 정리하며 원문·과거 결정은 보존한다.

## 에이전트 수정 증거와 버전업

수정 검증은 로컬에서 수행하고 원본 로그·캡처·검증 JSON·증거 묶음은 로컬에 보존한다. PR에는 수정 코드·문서와 검증 명령·결과 요약만 포함한다. 원본 증거를 제품·공통 Git 커밋·PR 첨부·원격 저장소에 업로드하거나 기존 증거를 삭제·이동하지 않는다. 에이전트 일반 실행은 과거 증거 전체를 필수 입력으로 요구하지 않으며 현재 작업에 필요한 검증은 별도로 수행한다.

PR 준비·리뷰·수정 대응 동안 증거를 유지한다. 버전업 준비에서 반영 PR·커밋과 로컬 증거 목록·중복·참조 상태를 점검할 수 있지만 이를 삭제·이동 권한으로 해석하지 않는다. 향후 실제 정리는 별도 명시 지시에 따라 대상·이유·처리 결과를 기록한다. 중요한 최종·실패·수정·재검증 원본과 미반영·미해결 작업의 근거를 유지한다. 로컬 선택 커밋 설치나 서버 재시작은 릴리스 완료가 아니다.

[버전업 지침 정비](releases/README.md#instruction-maintenance)와 같은 준비 단계에서 기록을 점검하되 담당 검토·메인 수락·실제 배포·프로젝트 설치는 구분한다. PR 제출 전 staged 파일·diff·본문·첨부에 원본 증거·비밀값·개인정보·제품 원문이 없는지 확인한다. [로컬 검증 절차](local-verification.md)를 함께 따른다.

## 적용 범위

문서·템플릿은 운영 계약이다. 자동 기록 생성·요약·검색 DB·삭제·릴리스 차단·증거 묶음·원격 업로드·백업 도구는 구현하지 않는다. 로컬 근거 경로는 원격 열람·백업을 뜻하지 않는다. 과거 원본을 확인하지 못하면 그 한계를 남기고 당시 PASS를 현재 결과로 승계하지 않는다. 새 clone의 프로젝트별 맥락을 자동 생성하거나 설치된 프로젝트를 조용히 갱신하지 않는다.
