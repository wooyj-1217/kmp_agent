# Project Goal

## 목적

**공통 하네스를 구축하고, 첫 제품을 만들면서 검증한다.** Codex 기반 역할 협업으로 작은 실제 기능을 기획부터 개발·실패 수정·재검증까지 수행하고 필요한 하네스 개선을 확인한다.
공통 설계는 [design.md](../design.md), 진행 순서는 [plan.md](../plan.md)다. 첫 제품·MVP·기술 스택은 UNKNOWN이며 제품별 입력으로 결정한다. [기존 제품 구조](product-architecture.md)는 해당 스택을 선택한 제품의 참조다.

## 확정된 설계 결정

기획은 문제·사용자·목표·MVP·정책·시나리오와 고유 ID의 수용 기준을 정의하고 요구사항의 확실성·출처를 기록한다.
기획·디자인 도구와 요금제는 미결정이다. ChatGPT Work·Figma·이미지 생성은 필수 의존성이 아니다. 제품 디자인 산출물은 design.md와 필수 HTML/CSS 시안이다. 상세 규격·상태·인계 조건은 [디자인 역할](roles/design.md)을 따른다.
프로젝트→기능→작업과 별도 PR 단위를 연결한다. 기록·배정·상태는 [작업 관리](task-management.md), 완료·버전·가정·사용자 질문은 [운영 설계](operations.md)를 기준으로 한다.
실행 상태·로그·사용량의 목표 계약과 실제 구현 범위를 구분한다. 새 문서 규칙이 자동 배정·독립 호출·PR 연동·시각 검토 게이트 구현을 뜻하지 않는다.
하네스 개선은 동일 평가 기준으로 효과를 확인한 뒤 채택한다.
세부 계약은 [역할 문서](roles/README.md)와 [운영 설계](operations.md)에 둔다.

## 이번 작업과 완료 조건

짧은 진입점과 상세 역할·제품·운영·구현 순서·미결정 문서를 작성한다.
완료 조건은 링크 유효성, 확정 기준과 역할 계약의 일관성, 미구현 기능의 PLANNED 표시다.
초기 문서화 작업에서는 제품 코드·실행 프로그램·자동화·도구 연동·배포를 구현하지 않았다. 후속 사용자 요청에 따른 최소 하네스 구현 범위는 아래 경계와 상태 문서를 따른다. 제품 코드는 계속 구현하지 않는다.

## 향후 성공 기준 — PLANNED

기획·검토 → 디자인 명세·HTML/CSS 시안·시각 검토 → 개발·검증·수정·재검증을 수행한다. 명세·시안 불일치를 해결한 뒤 개발에 인계한다. 과거 문서 연결 시험 완료는 제품 품질 검증 완료가 아니다.
요구·정책 문제는 기획, 디자인 문제는 디자인, 구현 오류는 개발로 반환하고 재검증한다.
입력·산출물·증거·버전·실행 이력·사용량을 추적하며 차단·예산 소진을 완료로 보고하지 않는다.

## 지침과 실행 시스템의 경계

AGENTS.md와 역할 문서는 참조 지침이며 자동 실행 시스템이 아니다.
사용자 요청으로 [최소 하네스 로거](harness-logging.md)의 JSONL 기록·명시적 세션 가져오기·실측 토큰 조회·파일 변경 관측을 부분 구현했다.
[최소 작업 관리](task-management.md)의 YAML 상태·의존성·검토·인계·역할 실행 ID·명시적 사용량 귀속도 구현했다.
독립 모델 실행 어댑터, 전체 오케스트레이션·예산 집행, 상시 자동 수집, 제품 자동 검증·평가는 **PLANNED**다. 제품 코드는 없다.
