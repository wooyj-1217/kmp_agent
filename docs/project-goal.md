# 프로젝트 목표

## 프로젝트 목표

**kmp_agent는 여러 제품 프로젝트에 설치해서 재사용하는 공통 개발 하네스다.**

AI에 개발을 맡겨도 사람이 요구사항·디자인의 세부사항을 반복 지시하고, 구현 누락을 확인하고, 변경 내용을 다시 전달해야 하는 부담을 줄이는 것이 목표다.

이를 위해 다음 흐름을 제공하는 것을 목표로 한다.

- 기획 → 검토 → 디자인·시안 → 개발 → 검증.
- 문제 발생 시 담당 역할로 반환 → 수정 → 재검증.
- 기획·디자인 변경 자동 감지 → 영향 분석 → 관련 구현 수정 → 재검증.
- 요구사항·산출물·피처 버전·작업·실행·검증 근거·사용량 연결 및 추적.

변경 반영은 사용자의 매번 별도 요청 없이 실행하는 것을 목표로 하며, 감시 대상과 변경 확정 조건은 적용 프로젝트에서 설정한다. 이 목표가 현재 전체 자동 실행을 지원한다는 뜻은 아니다.

## 공통 하네스와 적용 프로젝트의 경계

- kmp_agent는 역할, 실행 절차, 검증 체계, 추적 형식과 프로젝트 설정 인터페이스를 제공한다.
- 제품의 목표, 기능 범위, 기술 스택, 기획·디자인 원본, 인수 조건, 테스트 명령은 적용 프로젝트에서 정의한다.
- 제품별 산출물·코드·실행 로그·검증 증거는 해당 프로젝트에 보관한다.
- 제품의 기록이나 문제를 kmp_agent 원본 저장소로 자동 전송하지 않는다. [하네스 결함 개선 PR 정책](harness-defect-pr.md)에 따라 제품 정보가 없는 최소 재현·수정·검증 근거만 자동 개선 작업/Draft PR에 사용할 수 있다. 이는 제품 로그·산출물 전체의 자동 업로드 허용이 아니다. 머지·정식 배포는 사용자 승인 후 진행한다. 해당 자동 절차는 아직 미구현이다.
- 하네스 배포 버전과 적용 프로젝트의 피처 버전을 구분한다. 기존 Git·artifact 해시·P/D·CR 참조를 재사용하며 별도의 제품 버전 번호 체계를 강제하지 않는다.
- 특정 데모 제품의 목표나 구현 계획을 kmp_agent 자체의 목표로 포함하지 않는다. 예제는 사용법을 설명하는 자료로 구분한다.

하네스 업데이트와 제품의 기획·디자인 변경 반영은 별개다. 하네스 배포 버전은 [설치 안내](installation.md)에 따라 명시적으로 선택하며 개발 원본에서 자동 전파하지 않는다. 제품 변경 대응은 적용 프로젝트가 정한 감시·변경 확정 조건에 따르는 목표 흐름이다.

## 성공 기준

적용 프로젝트에서 전체 개발 흐름과 변경 대응을 수행할 수 있어야 한다.

효과는 사람 개입 횟수, 자동 검증 통과율, 검증되지 않은 완료 보고, 실패 후 자동 복구 성공률, 요구사항 변경 시 재작업 범위 등으로 평가할 수 있도록 지원한다. 구체적인 실험 시나리오와 목표치는 적용 프로젝트에서 정한다. 기획·정책의 의도된 결정과 오류·누락에 따른 개입을 구분하며, 미실행·미측정은 PASS나 0으로 표현하지 않는다.

공통 지표·증거 원칙은 [운영 설계](operations.md#개선-평가), 개발 계획과 현재 완료 범위는 [plan.md](../plan.md), 세부 구현 상태는 [design.md](../design.md#구현-상태)를 따른다. 예제나 임시 저장소 시험의 통과를 적용 프로젝트의 전체 제품 검증 완료로 간주하지 않는다.

## 현재 구현 상태와 남은 목표

| 범위 | 현재 상태 |
| --- | --- |
| 버전 고정 설치·프로젝트 연결·명시적 업데이트 | 구현·로컬 시험 완료. 원격 게시·실제 세션 설치 검증과 구분한다. [설치 안내](installation.md) 참조 |

| 개발 기준·대상 Git 코드 상태·검증 유효성 | 구현. 기존 입력에서 추적 설정 자동 연결 또는 누락 차단. 작업 명령·조회 시 변경을 확인하고 필요하면 RECHECK_REQUIRED로 표시한다. [개발 추적](development-tracking.md) 참조 |
| 프로젝트 설정 | 기술·API·정책·실행 안내·인수 조건의 단계별 고정 입력과 근거 정합성 검사 구현. [프로젝트 설정](project-settings.md) 참조 |
| 기획·디자인 상시 감시 → 변경 확정 → 의미상 영향 분석 → 구현 자동 수정 → 재검증 | **PLANNED**. 감시 대상·변경 확정 조건의 실행 설정 스키마와 전체 자동 실행기는 미구현 |
| 전체 제품 개발 오케스트레이션·실패 후 자동 복구·평가 자동 집계 | **PLANNED**. 일부 로컬 기록·검사와 전체 제품 실행·자동 복구를 구분한다 |

AGENTS.md와 역할 문서는 참조 지침이며 그 자체가 실행 시스템은 아니다. 이번 목표 정합성 작업은 문서만 수정하며 기능 구현·제품 개발·커밋·태그·푸시를 수행하지 않는다.
