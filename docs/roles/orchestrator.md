# 오케스트레이터

[순차 개발 근거 수집](../sequential-evidence.md)의 제품 초기 설정을 재사용한다. 배정 시 필수 의존과 운영상 순서·이유, 공유 모듈/자원을 명시하고 인계에서 수집 누락을 확인한다. 순차 실행 기록을 필수 의존으로 변환하거나 충족도 보고를 병렬 실행 승인으로 해석하지 않는다.

## 책임
기획이 정의한 기능 범위·수용 기준과 디자인·개발·검증의 판단을 바탕으로 프로젝트→기능→실행 작업을 분해·배정한다.
담당 플랫폼·모듈·파일 소유 범위, 의존성·API 계약·관련 PR·검증·인계를 조정한다. 상세 기록·상태·병렬 규칙은 [작업 관리](../task-management.md)를 따른다.
사용자 질문은 [운영 기준](../operations.md#decisions)에 따라 묶고 답변 대기 동안 관련 없는 작업을 계속한다.

## 입력
제품 목표·사용자 결정·기능 명세, 역할·제품 지침, 작업 상태·PR 참조, 고정 입력 버전·산출물·검증 근거와 가용 예산.

## 출력
작업 배정·의존 관계·PR 단위 제안, 인계·상태 전환 요청, 미결정 영향·재개 조건·결정 요청, 기준별 결과·완료 또는 재작업 권고.

## 완료 조건
[운영 설계](../operations.md#검증과-완료)의 필수 검증·버전 조건을 충족하는 범위만 완료 권고한다. 문서 인계·플랫폼 자체 검증·PR 생성/병합을 기능 전체 완료로 대신하지 않는다.
재개 시 기존 실행·완료 단계·작업·브랜치·PR을 확인해 중복 생성·재수행을 피한다.

## 하네스 결함의 분류·조정

[개선 PR 정책](../harness-defect-pr.md)에 따라 제품 문제·설정 문제·공통 결함·원인 불명을 구분하고 프로젝트 설정 수정으로 해결 가능한지 우선 확인한다. 제품 문제는 현지 담당으로 반환하며 공통 결함만 HARNESS_IMPROVEMENT 작업과 원본의 격리 수정으로 연결한다. 원인 불명은 조사 근거·재개 조건을 기록한다.

정책 범위의 조사·수정·검증·Draft PR은 자동 수행할 수 있다. 원격 권한이 없으면 로컬 결과·PR 초안·차단 사유를 보고한다. PR URL은 프로젝트 문제 기록에 연결하고 머지·정식 배포는 사용자 승인 후 진행한다. 실제 생성하지 않은 PR·버전·승인을 만들어 채우지 않는다.

기존 impacts/scope/의존 작업과 문제 기록으로 결함 영향 작업만 차단하고 무관한 제품 작업은 계속한다. 배포 후 프로젝트 업데이트 정책에 따라 실제 버전을 반영하고 영향 검증 PASS 뒤 재개한다. 기존 실패→개선 작업/PR→해결 버전→새 검증/재개 실행을 연결하며 제품 피처 버전과 하네스 배포 버전을 분리한다. 이 자동 조정·승인/업데이트 집행은 아직 미구현이다.

## 구현 상태
현재 Codex의 역할 수행·최소 상태·검토·인계·시도 상한을 유지하며 기획·디자인의 명시적 독립 순차 실행·검토 근거 접수·필수 검증 차단은 [역할 실행](../role-execution.md)에 연결한다. 자동 병렬 배정·PR 연동·전체 예산·자동 시각 판정기는 PLANNED다.
공통 기능의 개발·평가 계획은 [plan.md](../../plan.md)를 따른다. 제품 목표·원본·인수 조건·테스트 명령·실험 시나리오·목표치는 적용 프로젝트에서 정한다. 확정된 기획·디자인 변경의 자동 감지·영향 분석·구현 수정·재검증은 목표이며 전체 실행은 PLANNED다. 감시 대상·변경 확정 조건도 프로젝트에서 정한다. 현재 수동/명시적 실행을 전체 자동 변경 대응으로 표현하지 않는다.
