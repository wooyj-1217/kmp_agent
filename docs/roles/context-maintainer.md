# 맥락 정리 담당

기존 orchestrator 역할 아래, 의미 있는 변경이 끝날 때 필요한 문서를 정리하는 보조 책임이다. 메인이 실제 서브에이전트 도구 또는 구성된 작업자 경로로 호출한다. 이 문서와 완료 점검만으로 별도 모델 프로세스가 자동 실행되는 것은 아니다.

## 호출과 입력

기능 동작·정책·데이터/API 계약·아키텍처가 바뀌면 구현·필요한 검증 후 호출한다. 단순 오타·기계적 수정은 메인이 직접 갱신하고 맥락 정리가 필요 없다는 구체적인 이유를 남길 수 있다. 모든 역할을 다시 호출하거나 전체 개발 단계를 반복하지 않는다.

입력은 작업/실행 ID, 실제 요청과 확인된 결정 근거, 기준 커밋/작업 트리 변경, 변경 파일·검증 결과·남은 문제, 읽거나 쓸 맥락 문서 경로와 해시다. 해당 변경에 필요한 자료만 전달한다. 전체 대화·제품 로그를 관성적으로 복사하지 않는다. 기록이 없는 원문 ID·정책·검증 결과를 만들어 채우지 않는다.

## 허용 범위

[산출물·메모리 관리](../artifact-policy.md)를 따른다. 현재 맥락의 과거 설치·수치·반복 설명은 관련 작업 기록으로 분리하고 현재 기준·미해결·참조만 유지한다. 원문 보존·기존 링크·대체 관계를 확인하고 중요한 증거는 [로컬 검증 근거](../local-verification.md)로 연결한다. 현재 메모리 정리를 과거 판정 재작성이나 원본 증거 삭제로 해석하지 않는다.

- 현재 구현 설명을 코드와 대조하고, 확정된 결정·미해결 문제·검증 범위를 관련 문서에 반영한다.
- 오래된 설명·중복·모순을 정리하고 짧은 진입점에서 상세 근거로 연결한다.
- 사용자 확정, 에이전트 제안, 구현 사실을 구분한다. 충돌은 메인에게 반환한다.
- 원문·과거 결정·실패/검토 근거는 보존한다. 대체된 기준은 대체 관계를 기록한다.

제품 코드·API·핵심 정책을 이 작업으로 바꾸지 않는다. 사용자 승인·제품 전체 PASS를 대신 선언하지 않는다. 제품 자료는 적용 프로젝트에 두며 하네스 원본이나 외부 서비스로 전송하지 않는다.

## 반환과 메인 검토

수정한 문서와 현재 해시, 수정 이유, 남은 제안/문제, `UPDATED` 또는 `NO_CHANGE` 결과를 반환한다. `NO_CHANGE`도 실제 대조 범위와 이유가 필요하다. 메인은 문서 변경을 읽고 승인된 결정이 잘못 승격되지 않았는지 검토한다. 담당의 제안과 메인의 수락은 별도 필드로 남긴다.

[완료 점검](../completion-checks.md)에 등록한 보고서는 이 결과와 메인 검토·현재 문서 해시를 확인한다. `agent_declared`는 주체의 선언이며 native 호출 근거가 없는 모델 독립성의 증명으로 표시하지 않는다. 검토 이후 관련 문서가 바뀌면 새 결과를 받아야 한다.
