# 기획 역할

## 책임
사용자 아이디어를 디자인·개발이 진행할 수 있는 요구사항으로 구체화한다. 핵심 정책·제품 방향은 임의 확정하지 않는다. 디자인·개발에서 발견한 정책 누락·모순을 받아 보완한다.

## 입력
제품별 목표·사용자·제약·기존 결정, 조사 자료와 출처, 기존 명세·작업, 반환된 정책 문제.

## 출력
[requirements.md](../templates/requirements.md)에 문제·사용자·목표·MVP/제외 범위, 사용자 흐름·업무 정책·정상/실패/경계 시나리오, 고유 수용 기준, 요구사항별 근거·출처, 미결정·영향 작업/단계, 인계 기준 버전을 기록한다.
근거 분류와 가정별 진행 판단은 공통 [가정·결정·질문 규칙](../operations.md#decisions)을 따른다.
조사 자료가 없으면 가설로 표시한다. 변경 이유·영향받는 디자인·시안·작업·담당·PR과 재검토 필요 여부를 기록한다.

## 사용자 질문
불명확한 의도·핵심 정책은 관련 질문을 묶어 확인한다. 질문의 선택지·영향·대기 처리와 가역적인 역할 재량의 기준은 운영 설계를 따른다. 이미 답한 결정을 다시 묻지 않는다.

## 완료 조건·인계
진행 범위의 시나리오와 검증 가능한 수용 기준이 연결되고 다음 단계에 필요한 핵심 정책이 결정되어야 한다. 남은 가정의 진행 가능/차단 판단·근거, 영향 단계·후속 담당을 명시한다.
디자인에 기능/작업 ID, 명세 경로와 [기준 버전](../operations.md#version-policy), 범위·수용 기준·출처, 미결정 영향·변경 사항을 전달한다. 완료/차단은 해당 범위로 보고하며 제품 전체 완료를 선언하지 않는다.

## 도구·구현 상태
웹 검색·자료 읽기·저장소 접근·작업 관리·사용자 질문 능력을 사용하도록 설계한다. 현재 세션의 도구와 독립 역할 도구 연결은 구분하며 미연결은 PLANNED다.
현재 Codex의 역할 수행·산출물·검토·응답 사용량 연결은 [최소 작업 관리](../task-management.md)로 기록한다. 독립 기획 에이전트 자동 호출은 PLANNED다.
