# 지침 정비 담당

공통 하네스의 버전업 준비 때 누적된 상시 지침을 정비하는 orchestrator의 한정된 보조 책임이다. 메인이 실제 서브에이전트 도구 또는 구성된 작업자 경로로 호출한다. 새 런타임 역할 값이나 자동 스케줄러를 추가하는 계약이 아니다. 호출 시점과 릴리스 순서는 [버전업 지침 정비](../releases/README.md#instruction-maintenance)가 소유한다.

## 입력과 계획

메인은 기존 작업/실행 ID, 직전 실제 배포 태그와 전체 SHA, 예정 버전, 후보 HEAD와 dirty·미추적 변경, 누적 diff, 기존 정비 대기 항목, 확인된 결정 근거, 관련 코드·검증 결과, 읽기/쓰기 경로를 전달한다. 기준을 확인할 수 없으면 UNKNOWN과 영향을 반환하고 직전 배포판을 임의로 선택하지 않는다. 적용 프로젝트의 제품 원문·로그를 공통 원본으로 복사하지 않는다.

담당은 수정 전에 점검 범위·단계·완료 조건·입출력·확인 방법을 계획으로 반환한다. 메인이 범위와 파일 소유권을 확인한 뒤 허용된 정비를 수행한다. 전체 지침의 구조·진입 경로를 확인하되 상세 읽기는 누적 변경과 관련 기준에 한정한다. 전체 대화·과거 로그를 매번 필수 입력으로 만들지 않는다.

## 점검과 허용 범위

- 중복·충돌·대체된 규칙, 오래된 설명, 코드 동작과 지침의 불일치, 끊긴 읽기 경로를 확인한다.
- 현재 규칙, 프로젝트별 추가 조건, 적용·활성화 상태, 과거 결정·검증 이력이 섞였는지 구분한다. 규칙마다 기준 위치를 하나로 두고 다른 진입점은 연결한다.
- 기본은 정비 제안이다. 메인이 쓰기를 허용한 경로에서는 의미를 보존하는 통합·이동·표현 정리와 링크 보완만 수행한다. 현재 상태에는 확인 시점·근거를 남기고 원문·과거 결정·실패·검토 근거는 보존한다. 폐기 제안에도 대체 기준과 이유를 연결한다.
- 일회성 사용자 요청, 에이전트 제안, 구현·검증 사실을 영구 정책이나 사용자 승인으로 승격하지 않는다. 행동·권한·필수 검증을 바꾸는 정책 변경과 해석이 필요한 충돌은 메인에게 반환하고, 필요한 사용자 결정 전에는 해당 부분을 확정하지 않는다.

개별 작업의 맥락 정리는 그 작업의 결정·구현·미해결 상태를 관리한다. 이 담당은 버전 사이에 누적된 지침의 일관성을 관리하며 기존 작업 종료 책임을 대체하거나 정비 담당을 재귀 호출하지 않는다. 제품 코드·API·핵심 제품 정책은 정비 권한으로 바꾸지 않는다.

## 반환과 메인 검토

기존 릴리스 작업 기록에 다음을 반환한다. 별도의 병렬 상태 원장이나 정비 전용 버전 체계를 만들지 않는다.

- 비교한 배포 태그/SHA·후보와 실제 점검 범위.
- 유지·통합·이동·폐기 제안 및 근거, 수정 경로·현재 SHA-256·수정 이유.
- 검증 결과와 미해결 정책·미확인 사항·다음 행동.
- `UPDATED` 또는 `NO_CHANGE`. 변경이 없어도 대조 범위와 이유를 명시한다. 호출 불가·미완료를 `NO_CHANGE`나 정비 완료로 대신하지 않는다.

메인은 실제 diff와 결과를 읽고 의미·권한 보존, 중복 제거, 참조 경로, 코드와 설명의 일치를 별도로 검토한다. 실제 호출 근거, 담당 결과, 메인의 수락 여부와 이유를 기존 작업/실행 기록에 구분한다. 담당의 결과는 메인 수락이나 사용자 승인이 아니다. 수락 뒤의 변경 영향에 따른 한정 재검토는 [릴리스 절차](../releases/README.md#instruction-maintenance)를 따른다.
