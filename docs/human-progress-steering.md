# 실행 계획과 진행 표시의 설계 근거

다음은 기존 구현의 실행 계획·진행 표시 설계 기준을 공개용으로 요약한 것이다. 개인 대화 원문이나 사용자 메시지 식별자는 포함하지 않는다.

- 전체 실행 계획을 Todo로 먼저 등록하고 각 항목을 실제 task·검증 조건에 연결한다. 현재 런타임에는 별도 Todo 도구가 제공되지 않아 기존 native Tasks를 사용한다. 별도 수동 진행 상태를 만들지 않는다.
- 적용 제외는 이유·승인 근거를 보존하고 완료 체크하지 않는다. 대상은 확정된 요구사항의 명시 binding에서 생성하며 특정 플랫폼을 공통 절차에 박지 않는다.
- 대시보드는 프로젝트 전체의 기획·디자인·개발·QA, 인계·보완·차단·결정 사항을 요약한다. 서로 다른 실행·예제의 완료를 하나로 합산하지 않는다.
- CMD는 현재 실행의 전체 체크리스트와 활동·하위 에이전트·검증·재시도에 집중한다. 상단은 프로젝트 > 단계 > 현재 작업. 프로젝트 전체 완료로 표현하지 않는다.
- 전체 체크리스트 순서를 유지한다. 주요 단계 전환 시 재표시하고 명령마다 반복하지 않는다. 병렬 하위 작업·로그를 구별한다.

이 추가 지시로 공통 조회·Todo 등록·제외·프로젝트 요약 API를 보완하고 기존 같은 항목을 재검증한다. 작업 단계를 새로 늘리지 않는다. 설치본·제품·DB·원격은 이번 변경 대상이 아니다. 실제 독립 모델 역할 실행은 이번 표시 변경에서 새로 수행하지 않는다.
