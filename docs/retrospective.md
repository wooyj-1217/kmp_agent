### RETRO-H001 — 기획 역할 수행 중 도구 호출 실패

- 작업·실행: TASK-003 / 1317a3dc-ef9b-49bc-be46-aee3f20c062e.
- 기대/실제·영향: 기획 도구 호출을 기대했으나 SyntaxError로 실행 전 실패했다. 파일·작업 상태 변경 없이 같은 활성 역할에서 재호출했다.
- 근거: [시험 결과](../.harness/logs/trial-2-result.json)의 blocks, events.jsonl의 execution_block 이벤트 3099c9b1-43ed-4865-97d1-2c5ff28c3ee5.
- 원인: 오류 출력은 확인된 사실이다. 명령 문자열 구성 문제라는 판단은 에이전트 해석이며 하네스 구현 결함은 확인되지 않았다.
- 개선·재검증: 명령 문자열 수정 후 기획 제출·검토와 디자인 인계를 완료했다. 해당 도구 오류 자체의 독립 회귀 검증은 NOT_RUN이다. 별도 개선 작업·커밋·PR은 UNKNOWN.
- 배운 점·한계: 실행 전 호출 실패와 작업 상태 실패를 구분해야 한다. 재호출 성공을 하네스 전체 검증 통과로 확대하지 않는다.
- 반복 발생: 문서 정리 실행 d25bd59d-401a-4244-a706-4bebe3b7499a에서 AGENTS.md 패치의 예상 원문을 잘못 작성해 apply_patch가 일치 검증 실패로 거부했다. 근거는 해당 실행의 도구 오류 출력이다. 실패 시 파일 변경은 없었으며 원문 기준으로 수정 후 다시 반영했다. 영향은 편집 재시도이고 구현 결함은 확인되지 않았다. 오류 유형은 기존 SyntaxError와 다르지만 도구 입력 구성 오류라는 에이전트 분류로 이 항목에 연결한다.
- 반복 발생: 첫 커밋 준비 실행 807f07de-9ec6-4bf9-95c7-2f0e48d8ce76에서 git add가 .git/index.lock 쓰기 권한 제한으로 실패했다. 근거는 Operation not permitted 도구 출력과 승인 후 재시도 성공이다. 영향은 스테이징 지연이며 파일 내용 변경은 없었다. 환경 권한 제한은 확인된 사실이고 실행 환경별 권한 확인이 필요하다는 판단은 에이전트 해석이다. 기존 도구 실행 실패 항목에 연결하며 하네스 구현 결함으로 분류하지 않는다.

### RETRO-H002 — 역할 사용량의 일부만 귀속 가능

- 작업·실행: TASK-003·TASK-004 / 1317a3dc-ef9b-49bc-be46-aee3f20c062e.
- 기대/실제·영향: 역할 수행·검토 응답을 연결하려 했으나 관측 응답 9개 중 5개만 역할에 귀속했다. 나머지 4개의 사용량은 별도 소계로 남았다.
- 근거: [시험 결과](../.harness/logs/trial-2-result.json)의 attribution_evidence, unbound_details, usage_cutoff_at. 이는 해당 시험의 집계 시점 값이다.
- 원인: 역할 마커가 없는 응답 등이 포함되었다는 분류는 에이전트 해석이다. 원본 응답 ID·사용량과 명시적 귀속 목록은 기록으로 확인된다.
- 개선·재검증: 수행·검토 응답 ID 연결과 미귀속 소계 분리를 확인했다. 시험 중 실행기 구현 변경은 없었다. 별도 개선 작업·커밋·PR은 UNKNOWN.
- 배운 점·한계: 관측 사용량과 역할별 알려진 소계를 구분해야 한다. 관측하지 못한 호출·전체 비용은 UNKNOWN이며 시간 구간으로 역할에 추정 배분하지 않는다. 문서 인계 DONE은 제품·시각 검증 완료가 아니다.

### RETRO-H003 — 중단 대기와 검토 후 공백 구분

- 작업·실행: TASK-003·TASK-004 / 1317a3dc-ef9b-49bc-be46-aee3f20c062e.
- 기대/실제·영향: 실행 경과를 설명해야 했으나 디자인 검토 후 전체 공백만으로는 중단 대기를 판별할 수 없었다. 사용자가 모델 용량 오류 후 재개를 확인했다.
- 근거: [시간 보정 원본](../.harness/logs/trial-2-interruption-correction.json), [중단·재개 규칙](interruption-recovery.md). 원본 세션 사건 ordinal 714의 server_overloaded와 716의 다음 턴 시작을 기존 실행에 연결했다.
- 원인: 오류 기록과 사용자 진술은 각각 확인된 근거다. 두 턴을 같은 실행의 연속으로 연결한 것은 에이전트의 명시적 해석이다.
- 개선·재검증: 기존 중단·재개 구현으로 근거를 보완했다. 확인된 대기 611.387초, 하네스 실행 전체 1124.615초, 단계 합집합 345.576초, 미분류 167.652초다. 요청 시작 기준 미분류 184.013초와 구분한다. 반복 동기화에서 이벤트 수·대기 시간이 동일하고 작업 상태도 유지됐다. 별도 개선 TASK·커밋·PR은 UNKNOWN.
- 배운 점·한계: 검토 후 공백 693.789초 전체를 대기로 보지 않는다. 미분류·단계 경과를 실제 작업 시간으로 단정할 수 없으며 자동 복구가 구현된 것도 아니다.

### RETRO-H004 — 회고 대상 판단 기준 누락으로 추가 수정 요청 발생

- 작업·실행: 작업 ID UNKNOWN / 수정 실행 c95dc19e-8113-435f-94d6-1b4f9719baf7. 원본 작성 실행 bc843a99-a573-4797-b9b1-e4149dabe4ff.
- 기대/실제·영향: 회고 지침으로 기록 여부를 판단할 수 있어야 했으나 기존 지침에 시행착오 정의와 정상 결정의 제외 기준이 없었다. 사용자가 기준 보완을 요청해 공통 지침의 추가 수정이 필요했다.
- 근거: 이번 사용자 요청과 [기록 기준](task-management.md#retrospective). 수정 전 해당 파일 SHA-256은 ccf80ad143218110475ec9a8ce8869a3d263951fbb60c671c9fbf37fe90d59f7이며 원본 실행의 종료 로그에 같은 해시가 남아 있다.
- 원인: 정의·판단 기준 누락은 수정 전 문서에서 확인했다. 누락하게 된 원인은 UNKNOWN이다.
- 개선·재검증: 기록·제외 대상, 종료/인계·재개 판단, 반복 발생 갱신, 미확인 원인·효과와 교훈 처리, 자동 커밋·푸시 금지를 공통 기준에 보완했다. 문서 반영·참조·수동 메모 보존을 확인했다. 실제 후속 작업에서 과잉·누락 기록이 줄었는지는 UNKNOWN이다. 관련 커밋·PR은 미생성이다.
- 배운 점·한계: 작성 항목만으로 기록 여부를 판단하기 어려워 대상·제외 기준도 필요하다. 이번 사용자 보완 요청이 그 근거이며 후속 운영 효과는 아직 확인하지 않았다.
