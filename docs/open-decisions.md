# 남은 미결정 사항

공통 규격·역할·프로젝트/작업/PR·가정/질문 계약은 관련 기준 문서에 통합했다. 제품 모듈 합의는 해당 스택 선택 시 적용하는 참조이며 첫 제품 선정은 아니다.
아래는 실제 남은 세부 결정이다. 최소 로거의 부분 구현 범위는 [로깅 상태](harness-logging.md)를 따른다. 나머지 구현은 **PLANNED**다.

| ID | 항목 | 남은 결정 |
| --- | --- | --- |
| D1 | 첫 제품·목표·MVP | 제품 자체·실제 문제·사용자·핵심 정책·첫 기능과 수용 기준이 UNKNOWN |
| D2 | 실행 연결·권한 | Codex 연결 방식, 조사·질문·작업 관리 연결, 실행 권한 |
| D3 | 상태·예산 확장 | 최소 전환표·JSON 문법 YAML 원본·잠금·시도 상한은 구현. 일반 작업의 중단 복구·자동 재시도·시간·토큰·비용 한도와 일반 YAML 지원은 남음 |
| D4 | 로그 보관 | 원문·도구 결과 보관 범위, 마스킹·보존 기간·저장 위치 |
| D5 | 버전·환경 식별 | 정의 해시 범위·알고리즘, 하네스·평가·명세 버전 형식, 환경 고정 방법 |
| D6 | 사용량 수집 | 제공 필드·비용 출처·가격표 관리·시간 측정 경계 |
| D7 | 평가 프로토콜 | 평가 사례, 지표 분모·측정 구간, 비교 조건·채택 임계값 |
| D9 | 기획·디자인 도구·요금제 | 제작·브라우저 검토 도구·서비스·요금제; HTML/CSS 필수 산출물 규격은 확정. 특정 유료 서비스는 선행 조건 아님 |
| D8 | 첫 제품 스택·환경 | 채택 기술 스택·플랫폼·라이브러리·DI·빌드/검증 환경이 UNKNOWN. 기존 Ktor/KMP 합의는 해당 스택 선택 시 참조 |

담당 플랫폼·모듈·공유 코드 소유 범위, API 계약·저장소·브랜치/PR 관계는 제품 선정과 기능 분해 시 구체화한다. 공통 필드·상태 계약은 [작업 관리](task-management.md)에 이미 정의했으며 새 런타임 지원은 PLANNED다.

사용자 제품·정책 결정과 기술적 구현 결정을 구분한다. 기획은 핵심 정책을 임의 확정하지 않는다.
변경 시 결정·근거·날짜·명세 버전·영향 작업을 기록한다.
