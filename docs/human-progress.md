# 사람이 읽는 작업 진행 체크리스트

## 원본 요구와 완료 조건

2026-10-28 사용자 요청은 대시보드와 진행 메시지가 같은 native task/agent_run/검증 상태를 설명하도록 하는 것이다. 사용자 최신 형식 지시: 전체 주요 단계를 같은 순서로 표시; 유효 결과·필수 근거가 확인된 것만 [x], 나머지 [ ]; 실제 최근 활동이 관측되는 항목만 굵게 진행 중; 대기/차단/재검증을 항목 옆에 표시; 세부 활동·재시도는 해당 항목 안; 주요 전환에 전체 체크리스트 재표시; 개별 도구마다 반복 금지. 개별 명령/시험 함수는 주요 단계가 아니다. 단계 번호는 순서이며 시간 진행률이 아니다. 원문 메시지 식별자는 수집 확인 전 UNKNOWN.

이번 작업 단계는 native task로 등록한다: 기존 상태와 표시 경로 조사 → 공통 진행 요약 구현 → 대시보드·에이전트 메시지 연결 → 상태별 시험·브라우저 확인·결과 정리. 조사·초기 코드 작성 후 연결한 부분은 사후 등록이며 실제 최초 시작 시각으로 소급하지 않는다. 이후 상태는 native task와 실제 근거만 갱신한다.

## 설계·조회 API

`harness.human_progress.project(snapshot, raw_tasks)`가 읽기 전용 공통 모델이다. 상태표를 따로 저장하지 않는다. 기존 dashboard.task_view가 검사한 필수 criteria/출력/입력/코드/승인 기준 유효성과 원본 의존·부모 관계를 사용한다. 하위 작업은 명시 부모 아래 묶고 부모 및 하위 필수 근거를 확인한다. 재시도는 기존 executions 수·실패/복구 이력으로 설명한다. 명령 종료0, DONE 자기 보고, 요청 접수는 완료가 아니다. 실행 중 표시는 최근 실행 관측이지 프로세스 생존 보증이 아니다.

제품 코드의 기술 준수 조건은 기존 product/acceptance 계약을 지킨다. 하네스 코드 작업에 제품 UI 계약을 임의로 강제하지 않고 해당 작업의 필수 검증·코드 고정 근거를 검사한다. 출처 미확인 상태를 완료로 만들지 않는다.

대시보드 `/api/snapshot`의 human_progress와 agent_message, CLI `python -B -m harness.human_progress --root ROOT --scope SCOPE [--start|--json]`가 동일 조회를 사용한다. 역할·개발 위임·QA context에 동일 진행 조회와 메시지 지침을 연결한다. 메인 에이전트는 주요 단계 전환/문제/복구 때 조회해 설명한다. 이 지침이 세션 밖 자동 메시지 발송기나 프로세스 heartbeat를 구현한 것은 아니다.

## 오류·재시도·계획 변경

기존 `Tasks.fail`에 선택형 failure_category/failure_evidence/next_action/requires_human/decision_question을 받는다. category=PRODUCT_DEFECT/HARNESS_DEFECT/ENVIRONMENT/UNKNOWN. 분류·사람 질문은 실제 근거와 함께 명시해야 한다. 텍스트나 work_type에서 원인을 추측하지 않는다. 원본 실행에 기록하고 재시도해도 이전 실패를 보존한다. 분류 없는 과거 오류는 UNKNOWN. 사람 결정 여부 미기록을 없음으로 단정하지 않는다.

작업·부모·의존 관계가 계획의 원본이다. 작업 추가·범위 제거는 조회 시 표시하고 이유가 기록되지 않았으면 이유 기록 없음으로 남긴다. 추가/삭제/보완을 감추거나 새 진행표로 리셋하지 않는다. 대시보드의 이전 조회 비교는 브라우저 메모리에서만 수행하며 원본 상태 원장이 아니다. 에이전트는 실제 변경 이유를 native task/반환 이력에 남긴다.

## 검증 범위

미선택·근거 없는 DONE·정상 진행·병렬·선행 차단·하위 작업·재시도·재검증·사람 결정·오류 분류·과거 실행·기간 필터·조회 불변을 검사한다. 기존 대시보드/역할/QA/개발 호출 회귀도 변경에 맞춰 확인한다. 실제 브라우저에서 체크리스트·상세·재조회·좁은 화면을 확인한다. 합성 사례와 현재 실제 하네스 작업 기록을 구분한다. 제품 기능·설치본·DB 변경이나 원격 배포는 하지 않는다.
