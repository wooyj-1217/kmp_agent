# v0.4.1 지원 현황

VERSION **0.4.1**, 태그 **v0.4.1**의 제공 범위다. 비교 기준은 [v0.4.0](v0.4.0.md), 최종 SHA·원격 설치/update·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.1)에서 확인한다. 이전 태그와 배포 기록은 유지한다.

## v0.4.0 이후 변경

- 설치 프로젝트의 PreToolUse·Stop에 기존 작업 원장·native 세션·승인·단계·동결 기술 계약을 검사하는 guard를 추가했다. 미등록/TODO 제품 소스 수정과 미완료 상태의 게시·종료를 차단한다.
- 제품 원본의 기술 제약을 파생 기획 승인으로 덮어쓰지 못하도록 현재 native 인간 승인과 코드 소유 경로·소스 패턴을 확인한다. 공통 하네스가 제품 스택을 임의로 고정하는 기능은 아니다.
- 직접 인터프리터·불명확한 실행·제어 파일 수정과 Git 읽기 옵션의 프로그램 실행·출력 우회를 차단한다. 역할 worker·QA·개발 위임의 실행 adapter도 검사한다.
- init은 기존 제품 훅을 보존하며 검사 훅을 병합한다. [제품 도구 검사](../product-tool-enforcement.md)의 명령·신뢰·제한을 따른다.

## 업데이트와 사용 전제

제품 루트의 사용자 터미널에서 `rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.1`을 실행한다. 새 설치는 [설치 안내](../installation.md)의 v0.4.1 bootstrap을 사용한다. 업데이트는 제품 원본·기존 로그·동결된 완료 이력을 재작성하지 않는다.

업데이트 뒤 `/hooks`에서 기존 수집 훅과 새 PreToolUse·Stop 검사 훅을 검토·신뢰하고 새 Codex 세션에서 활성 상태·실제 허용/거절을 확인한다. `status`의 VERIFIED는 수집 근거이며 guard의 실행 차단 인증이 아니다. guard가 활성화된 Codex 도구 안에서 init/update/recover를 raw 실행하지 않고 사용자 터미널을 사용한다.

기술 계약 이전의 일반 읽기·기획용 문서 준비는 허용된다. 제품 소스 수정·명령 실행은 승인된 계약·관리 경로가 필요하므로 기존의 직접 실행 습관과 호환되지 않을 수 있다. 훅 신뢰 우회·비활성화로 해결하지 않고 계약·지원 경로를 보완한다.

## 검증 범위와 제한

v0.4.1 작업 트리에서 guard·설치·프로젝트 연결·기술/단계 계약·역할·release·PR 범위 관련 테스트 130개를 통과했다. 이후 문서 정리와 최종 커밋 사이 실행 코드·테스트·VERSION의 동일성을 대조한다. 원격 신규 설치·v0.4.0 업데이트·실제 훅 검증은 최종 Release 본문에 실제 결과로 확정한다. 준비 중인 후보를 배포 완료로 표시하지 않는다. PR #14에서 동일 guard 코드의 임시 설치 프로젝트 실제 Codex v0.167.1 신뢰·로드/읽기 허용/3개 도구 거절/미완료 TODO Stop 차단을 확인했으며, 후보의 관련 모듈 해시 일치를 확인했다.

기존 위임 테스트 `test_missing_authority_blocks_without_masking_review_failure`의 `DONE != BLOCKED` 실패는 변경 전 main에서도 재현됐다. 전체 회귀 PASS로 표시하지 않는다. 실제 모델의 기획→디자인→구현→QA 전체 E2E와 실제 적용 제품 전체 인수는 미실행이다.

guard는 지원되고 신뢰·활성화된 Codex 훅 경로의 보호 장치다. OS sandbox나 서버 branch protection이 아니며 훅 비활성화·미신뢰·import 실패·timeout·기존 write_stdin 세션·Codex 밖의 수동 변경을 보장하지 않는다. 임시 검증 프로젝트 결과를 모든 환경이나 제품 품질로 확대하지 않는다.
