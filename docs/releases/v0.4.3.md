# v0.4.3 지원 현황

VERSION **0.4.3**, 태그 **v0.4.3**의 제공 범위다. 직전 실제 배포 [v0.4.2](v0.4.2.md), 커밋 `d0b05fcbd22b4f62046e3e4de10d69e3666594ea`와 비교한다. 최종 커밋·원격 검증·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.3)에서 확정한다.

## v0.4.2 이후 수정

설치된 제품 guard가 공식 update 진입점도 미분류 실행으로 차단하던 문제에 관리 업데이트 경로를 추가한다. 설치 모드의 공식 `.kmp-agent/agent.py update --ref <태그|40자리 SHA>`를 Python 3로 호출하는 경로만 지원하며 기존 source를 재사용한다. 권장 실행 이름은 `python3`이며 Python 3 환경의 `python`도 분류한다. `rtk proxy` wrapper를 사용할 수 있다.

guard와 CLI의 공통 계약은 공식 launcher 원문·선택 runtime 경로·커밋 SHA·Git clean 및 실제 CLI argv를 검사한다. `--source`는 같은 값이어도 거부하며 target 덮어쓰기·개발 모드·임의 bootstrap·clone·추가 실행 인자를 허용하지 않는다. 제품 구현·완료 계약 없이도 이 명시적 관리 명령을 분류하되, 제품 소스 변경이나 검토 생략 권한으로 확대하지 않는다. [지원 경계](../guard-capabilities.md#설치본의-명시적-관리-업데이트)를 따른다.

`init`·`recover`는 계속 사용자 터미널에서 실행한다. 자동 최신 버전 선택·원본 변경 전파·실제 제품 자동 업데이트를 제공하지 않는다. v0.4.2의 CUA·작업 조회·외부 Git 경계와 단계 계약·개발계획 독립 검토는 유지한다.

## 설치·첫 전환·후속 업데이트

v0.4.2의 기존 guard는 새 버전의 관리 경로를 알지 못하므로 첫 v0.4.3 전환은 사용자 터미널에서 **새 v0.4.3 bootstrap**으로 수행한다. 기존 설치 사본을 직접 수정하거나 훅을 비활성화하지 않는다.

```sh
rtk proxy git clone --depth 1 --branch v0.4.3 git@github.com:wooyj-1217/kmp_agent.git /tmp/kmp-agent-bootstrap
rtk proxy python3 /tmp/kmp-agent-bootstrap/bootstrap.py update --source git@github.com:wooyj-1217/kmp_agent.git --ref v0.4.3 --target /path/to/product
```

게시된 태그와 아직 없는 bootstrap 경로, 실제 제품 Git 루트를 사용한다. 이 사용자 터미널 bootstrap 명령의 `--source`·`--target`을 제품 guard 내부 관리 update의 허용 옵션으로 해석하지 않는다.

v0.4.3 설치 후에는 공식 `.kmp-agent/agent.py update --ref <게시된 태그|40자리 SHA>`로 다음 버전을 명시적으로 선택할 수 있다. 제품별 적용 정책·현재 사용 버전과 실제 훅 활성 상태를 확인한다. 설치 성공·status의 VERIFIED는 실제 guard 허용/차단·제품 인수와 별도다. 상세는 [설치 안내](../installation.md)를 따른다.

## 검증 범위

v0.4.2 설치본의 정상 update 거부를 재현하고, 작업본에서 신규 계약 16개를 포함한 관리 update·기존 guard·설치 회귀 **96개 PASS**를 확인했다. 실제 CLI를 사용하는 합성 fixture에서 업데이트 후 새 guard 선택·기존 source/프로젝트 ID/파일/로그 보존, 차단·손상 제품 원장 보존을 검사했다. 구문 오류·control alias/FIFO·shell override 등 독립 검토 지적을 수정하고 핵심 **4개 재검증 PASS**를 확인했다.

이 기록은 실제 신뢰된 Codex 훅 실행과 구분한다. clean checkout 및 최종 원격 태그 신규 설치·init·재설치·v0.4.2→v0.4.3 최초 전환과 설치 후 관리 update 결과·최종 SHA는 Release 게시 본문에서 확정한다. 과거 v0.4.2의 회귀·원격 설치 결과를 이번 변경의 PASS로 승계하지 않는다.

실제 적용 제품 업데이트, 실제 Codex 세션의 훅 신뢰·도구 전달·업데이트 실행, 제품 작업 재개·전체 인수는 이 공통 수정의 합성 검증과 별도다. 원본 증거는 로컬에 보존한다.
