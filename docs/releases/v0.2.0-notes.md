# v0.2.0

> 게시 원본: 아래 `{{RELEASE_COMMIT}}`과 `{{REMOTE_INSTALL_RESULT}}`는 태그 게시 후 확인한 값으로 GitHub Release 본문에서 대입한다. 태그 안의 자기 커밋 SHA를 미리 생성하지 않으며 미확정 표시가 남은 본문은 게시하지 않는다.

## 이번 버전 요약

기획·디자인을 독립적으로 실행하고, 버전이 고정된 산출물·검토 결과를 개발 입력 해석과 수동 구현 작업 추적에 연결할 수 있습니다. 프로젝트별 앱·웹·서버 지원 범위와 단계별 필수 입력을 기록하고, 순차 개발의 실행·검증 근거를 수집할 수 있습니다.

## 이전 배포 버전 대비 변경

비교 기준: v0.1.0 → v0.2.0.

- **추가:** 기획·디자인 실행과 기준본 보관, 요구사항–화면·상태 대응, 검토 문제 반환·수정·재검증 인계 조건을 제공합니다. 독립 개발 역할은 지정 버전의 입력을 읽고 구현 계획을 작성합니다.
- **추가:** 앱·웹·서버 범위와 미정 사항을 기록하고, UI·클라이언트 연동·서버·통합 검증별 착수 조건을 구분합니다. 수동 구현 작업과 명령 래퍼의 변경·검증 근거를 추적합니다.
- **변경:** 훅은 빠른 원본 수집·저장에 집중하며 개입 연결·집계·프로젝트 검사는 별도 명령으로 수행합니다. 이 후처리를 훅 성공만으로 완료했다고 판단하지 않습니다.
- **수정:** 긴 세션에서 원본·누적 이벤트를 반복 해석하던 수집 경로를 증분 변환·배치 저장으로 개선했습니다. 부분 줄 보류, 중단 후 재수집, 같은 세션 동시 호출 보호와 실제 수집 자식 종료 확인을 추가했습니다. 훅 제한 시간을 늘리는 방식은 사용하지 않았습니다.

## 지원 범위와 제약

역할 실행·검토·다음 역할 호출은 **수동**입니다. 각 명령 안에서는 입력 고정·산출물 보관·검증 게이트·근거 수집을 처리합니다. 기획 변경의 상시 감시, 역할 간 무지시 자동 연쇄, 독립 코드 구현 worker, 병렬 개발 실행기와 자동 Draft PR 생성은 제공하지 않습니다.

디자인 시안의 브라우저·시각 검토는 별도 수행해야 하며 앱 HTML 시안은 네이티브 동작 검증이 아닙니다. 사용량·비용은 미귀속/UNKNOWN이 남을 수 있습니다. 증분 수집에도 원본 무결성 확인을 위한 이전 바이트 해시와 배치당 이벤트 로그 읽기 비용이 남습니다. POSIX 환경·Python 3.10+·Git·rtk가 필요하고 실제 역할 실행에는 Codex 환경·권한이 필요합니다.

[태그 기준 지원 현황](https://github.com/wooyj-1217/kmp_agent/blob/v0.2.0/docs/releases/v0.2.0.md)

## 설치·업데이트와 마이그레이션

v0.2.0 태그로 설치하거나 업데이트합니다. 설치 대상 `./my-project`는 기존 Git 프로젝트로 바꾸고 `kmp-agent-bootstrap`은 아직 없는 폴더를 사용합니다.

```sh
rtk proxy git clone --no-checkout https://github.com/wooyj-1217/kmp_agent.git kmp-agent-bootstrap
rtk proxy git -C kmp-agent-bootstrap fetch origin refs/tags/v0.2.0
rtk proxy git -C kmp-agent-bootstrap checkout --detach FETCH_HEAD
rtk proxy python3 kmp-agent-bootstrap/bootstrap.py install --source https://github.com/wooyj-1217/kmp_agent.git --ref v0.2.0 --target ./my-project
```

기존 설치는 대상 프로젝트 루트에서 실행합니다. 최신 버전을 자동 추적하지 않으므로 ref를 명시해야 합니다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.2.0
rtk proxy python3 .kmp-agent/agent.py status
```

- install/update는 init을 포함하지만 설치 성공이 실제 세션 수집 성공을 뜻하지는 않습니다. `/hooks`에서 UserPromptSubmit·Stop 정의를 검토·신뢰하고, 갱신된 지침·시작 설정은 새 Codex 세션에서 확인하세요. 기존 직접 참조 훅의 소유권이 불명확하면 자동 전환하지 않고 충돌을 보고하므로 별도 정리가 필요합니다.
- 순차 근거 수집을 사용할 프로젝트는 모듈·명령 설정 JSON을 준비하고 `rtk proxy python3 .kmp-agent/agent.py init --tracking-settings tracking-settings.json`으로 등록하세요. 기존 설정의 보존·변경 범위도 확인해야 합니다.
- 개입 연결·집계·등록 프로젝트 검사가 필요하면 별도 후처리를 실행하세요. 설치 정보의 `commit`을 `<SHA>`에 대입해, 예를 들어 `rtk proxy python3 ".kmp-agent/releases/<SHA>/harness/collection_maintenance.py" --root . link`를 실행합니다. status/projects 등은 [태그 기준 후처리 안내](https://github.com/wooyj-1217/kmp_agent/blob/v0.2.0/docs/hook-collection.md)를 따릅니다.
- 기존 이벤트 형식·source_key·식별자는 유지하고 세션 커서·배치 복구 메타데이터를 추가합니다. 로컬 시험에서는 제품 파일·로그·프로젝트 ID·설정 보존과 실패 복구·이전 SHA 롤백을 확인했습니다. 이를 모든 사용자 설정의 무조건적 호환이나 데이터 백업 불필요로 확대하지 않습니다. 불완전 업데이트는 `rtk proxy python3 .kmp-agent/agent.py recover`로 복구합니다.

[태그 기준 설치 안내](https://github.com/wooyj-1217/kmp_agent/blob/v0.2.0/docs/installation.md)

- **로컬 후보:** 전체 회귀와 임시 Git SHA의 설치·init·update·실패 복구·롤백·설정 보존을 확인했습니다. 이후 문서만 변경된 후보에는 코드/fixture 동일성을 대조하고 설치·문서 명령을 재검증했습니다. 긴 세션 CLI 수집·중단 복구·중복 방지·별도 후처리도 확인했습니다. 추가된 릴리스 문서를 최종 후보에 포함하고 코드·fixture 동일성, 문서·명령·링크와 설치 보존 범위를 다시 대조했습니다.
- **원격 태그 검증:** {{REMOTE_INSTALL_RESULT}}
- **공통 예제:** 과거 작업본에서 기획→디자인·앱/웹 HTML 시안 검토→수정 반환→개발 입력 해석을 실행했습니다. 이번 최종 배포 커밋에서 실제 Codex 역할·브라우저 전체 흐름을 다시 실행한 결과는 아닙니다. [공통 예제의 범위](https://github.com/wooyj-1217/kmp_agent/blob/v0.2.0/docs/examples/role-execution/connection-report.md)를 참조하세요.

- **미실행·미확인:** 설치본 새 Codex 세션·실제 제품 전체 개발·KMP 앱/웹/서버 구현·빌드. 원격 설치 PASS를 이 항목의 PASS로 확대하지 않습니다.
