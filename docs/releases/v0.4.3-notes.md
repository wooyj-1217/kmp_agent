# v0.4.3 — 설치본 관리 업데이트 경로 수정

제품 guard가 공식 update 진입점까지 차단하던 문제를 수정합니다. 설치 모드에서 `python3 .kmp-agent/agent.py update --ref <태그|40자리 SHA>`를 명시적 관리 경로로 지원하며 기존 설치 source를 재사용합니다.

## v0.4.2 대비 수정과 지원 경계

guard와 CLI가 공식 launcher 원문·runtime 경로·커밋 SHA·Git clean 및 실제 argv를 같은 계약으로 확인합니다. `--source`는 기존 값과 같아도 허용하지 않으며, target 덮어쓰기·개발 모드·임의 bootstrap·clone·추가 실행 인자는 허용하지 않습니다. `init`·`recover`는 계속 사용자 터미널 명령입니다. 제품 구현·검토·완료 gate와 CUA·Git의 기존 제한은 유지합니다.

[0.4.3 지원 현황](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.3/docs/releases/v0.4.3.md)

## 설치·업데이트와 첫 전환

v0.4.2의 기존 guard에는 새 지원이 소급 반영되지 않습니다. 첫 v0.4.3 전환은 사용자 터미널에서 **새 v0.4.3 bootstrap**으로 수행하세요. 게시된 태그, 아직 없는 bootstrap 경로와 실제 제품 Git 루트를 사용합니다.

```sh
rtk proxy git clone --depth 1 --branch v0.4.3 git@github.com:wooyj-1217/kmp_agent.git /tmp/kmp-agent-bootstrap
rtk proxy python3 /tmp/kmp-agent-bootstrap/bootstrap.py update --source git@github.com:wooyj-1217/kmp_agent.git --ref v0.4.3 --target /path/to/product
```

신규 설치는 같은 bootstrap의 `install --source git@github.com:wooyj-1217/kmp_agent.git --ref v0.4.3 --target /path/to/product`를 사용합니다. 위 bootstrap의 source·target 옵션은 제품 guard 안의 관리 update 옵션이 아닙니다.

v0.4.3 설치 후 다음 명시적 업데이트부터 아래 경로를 사용할 수 있습니다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref <게시된-태그-또는-40자리-커밋-SHA>
```

`/hooks` 정의·신뢰·새 세션의 활성 상태와 실제 허용/차단을 별도로 확인하세요. 훅 비활성화·설치 파일 직접 편집은 전환 방법이 아닙니다. 제품별 적용 정책과 기존 데이터·로그·원장은 유지하며, 실제 적용 제품 업데이트를 이 릴리스 작업에서 자동 수행하지 않습니다.

[0.4.3 설치 안내](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.3/docs/installation.md)

## 검증 범위

수정 전 거부를 재현하고 작업본에서 신규 계약 16개를 포함한 관련 회귀 **96개 PASS**, 독립 검토 지적 수정 후 핵심 **4개 재검증 PASS**를 확인했습니다. 실제 CLI 합성 fixture의 자료 보존·새 guard 선택과 우회 거부를 확인했으며 실제 신뢰된 Codex 훅 실행을 대신하지 않습니다. clean checkout·최종 원격 태그 설치/update와 v0.4.3 설치 후 관리 update 결과·최종 SHA는 게시 본문에서 확정합니다. 과거 v0.4.2 결과를 이번 수정의 PASS로 승계하지 않습니다. 실제 제품 업데이트·실제 세션 훅 활성화·제품 작업 재개와 전체 인수는 별도 검증 대상입니다. 원본 증거는 로컬에 보존합니다.
