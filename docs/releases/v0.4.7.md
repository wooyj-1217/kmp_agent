# v0.4.7 지원 현황

VERSION **0.4.7**, 태그 **v0.4.7**의 제공 범위다. 직전 실제 배포 [v0.4.6](v0.4.6.md), 커밋 `61ee78de586980b084e5aa178a132002002e4fb2` 이후 [PR #25](https://github.com/wooyj-1217/kmp_agent/pull/25)를 포함하는 패치다. 준비 기준은 머지 커밋 `ab60e0ca5fea199039e473e5fd7beb6ed3c23c7d`이며, 최종 배포 SHA·원격 검증·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.7)에서 확정한다.

## v0.4.6 이후 수정과 추가

- UI 질문의 줄바꿈 정규화·UTF-8 512바이트 절단을 지원한다. 표시용 접두어만으로 승인하지 않고 네이티브 호출 ID·질문 인덱스·도구·전체 질문·선택지·동결 계약과 현재 파일을 검증한다.
- 서로 다른 시점에 열린 질문의 batch 응답을 항목별로 검증한다. 같은 call/item의 중복·상충 응답은 등록·복구·소비 시점에 현재 원문 끝까지 확인해 차단한다.
- typed 승인 질문은 등록할 때 canonical 선택지 ID `approve`를 요구한다. 기존 `APPROVE-T1` 같은 ID는 변경하거나 승인 권한으로 승격하지 않는다.
- 공식 `task --operation recover-question`으로 기존 원문 응답과 당시 계약·현재 범위를 다시 검증한다. 성공·거절 감사 기록을 남기고 실패 시 답변 상태를 보존한다. 반복 복구도 재검증하며, 원문 복구와 승인 소비 가능 여부는 구분한다.
- 제품 cwd guard는 유지하며 하네스 수정은 원본 checkout의 별도 세션으로 인계하도록 위치·자료를 안내한다.

세부 계약과 복구 입력은 [승인 권한](../approval-authority.md), [실행 정책](../execution-policy.md), [도구 경계](../guard-capabilities.md), [하네스 결함 인계](../harness-defect-pr.md)를 따른다. 복구는 잘못된 질문의 자동 이전이나 제품 구현 승인이 아니다.

## 설치·전환

신규 설치는 [설치 안내](../installation.md)의 v0.4.7 bootstrap을 명시 선택한다. v0.4.3~v0.4.6 설치본은 기존 source를 재사용하는 단일 관리 명령을 사용한다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.7
```

다른 셸 명령·`--source`·`--target`과 결합하지 않는다. v0.4.2 이하는 사용자 터미널의 새 bootstrap으로 전환한다. 선택 SHA·runtime을 확인하고 새 세션에서 훅 신뢰·활성을 검증한다. 기존 원장·답변·선택지 ID를 자동 변경하지 않는다. 실제 제품 설치본은 이 릴리스 작업에서 변경하지 않는다.

## 검증 범위

PR #25와 동일한 구현에서 전체 수집 921개 중 905개 PASS를 확인했다. 실행 집계는 912개이며, 오류 8건은 모두 샌드박스의 로컬 socket.bind PermissionError다. 동일한 오류 8건이 v0.4.6 기준에서도 재현됐고, setUpClass 차단으로 9개 테스트는 실행되지 않았다. 깨끗한 checkout의 승인 전달·복구·가드·설치 관련 47개 PASS, 독립 코드 검토에서 추가 결함 없음, 14개 변경 파일의 범위·해시·상대 링크 대조 PASS를 확인했다.

기존 PR의 동일 실제 Codex UI 원문 응답으로 정규화·절단 거절 전후를 비교한 복구·typed 승인 소비 시험은 임시 시험 계약에 한정한다. 제품 승인·인수나 전체 모델 E2E 성공을 뜻하지 않는다. 버전·문서 후보의 영향 검사와 신규 설치·init·재설치·v0.4.6→v0.4.7 업데이트, 최종 커밋과 원격 태그의 검증 결과는 Release 게시 본문에서 확정한다.

신뢰된 실제 설치본 훅·실제 모델 전체 E2E·공통 예제·실제 제품 업데이트/인수는 **NOT_RUN**이다. Chrome 시작 실패와 RESTART_REQUIRED의 원인은 **UNKNOWN**이며 이번 변경의 해결 항목이 아니다. 로컬 대시보드 HTTP 검증은 샌드박스 제한으로 **BLOCKED**다. 검증 원본·실제 UI 원문·제품 자료는 로컬에 보존하고 공개하지 않는다.
