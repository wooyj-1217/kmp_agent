# v0.2.0 지원 현황

VERSION **0.2.0**, 태그 **v0.2.0**의 지원 계약이다. 최종 배포 SHA는 태그가 가리키는 커밋이며 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.2.0)에서 전체 SHA·원격 설치 결과·게시 여부를 확인한다. 후보 단계의 기준 HEAD와 내용 해시·검증 적용성은 [준비서](candidate-preparation.md) 및 [manifest](candidate-manifest.json)에 보존한다. VERSION 문자열과 실제 설치 SHA를 함께 대조한다.

이 문서는 kmp_agent 제공 범위다. 적용 프로젝트의 목표·스택·개발 상태는 입력이나 평가 대상이 아니다. 과거 공통 예제는 해당 과거 작업본에서의 실행이며 이번 후보에서 실제 LLM/브라우저 전체 흐름을 다시 실행했다는 뜻이 아니다. 후보의 현재 실행 근거는 임시 로컬 Git 저장소에서의 전체 회귀·설치/업데이트·복구 시험이며, 최종 원격 태그 설치 검증은 태그 게시 후 GitHub Release 본문에 기록한다. 설치본의 새 Codex 세션은 NOT_RUN이다.

## 0.2.0 수집·운영 변경

- 실제 Codex 자동 훅에서 수신 1.010초·Stop 1.032초·수집 자식 종료 코드 0, 요청/응답 각각 1회·중복 0을 확인했다. 이 하네스 장기 세션에서의 증거를 보존하며 원격 설치판의 자동 훅 PASS로 확대하지 않는다.
- 훅은 세션 증분 수집·배치 저장·커서 확정만 수행한다. 전체 probe·개입 연결·집계·프로젝트 검사는 [명시적 후처리](../hook-collection.md)로 분리했다. 종료가 확인되지 않으면 UNKNOWN이며 120초를 늘리지 않았다.
- 기존 CLI full sync는 전체 변환·자동 연결을 호환 유지하되 같은 배치 저장기를 사용한다. 긴 세션·저장 확정 후 중단/재수집과 분리된 후처리를 후보 회귀로 검사한다.
- 수동 기획→디자인→브라우저 검토→수정 반환→개발 입력 해석/계획과 별도 수동 구현·검증 추적이 제공 범위다. 자동 제품 구현 worker·상시 변경 감시·역할 자동 연쇄·병렬 개발·자동 Draft PR은 제공하지 않는다.

## 사용 전제와 검증 경계

POSIX(macOS/Linux)·Python 3.10+·Git·rtk가 필요하다. 독립 역할의 실제 모델 실행은 Codex 환경·권한이 추가로 필요하다. 설치 후 대상에서 훅 정의를 검토·신뢰하고 시작 입력이 바뀌면 새 세션으로 확인한다. UI 시안은 HTML/CSS이며 앱의 실제 네이티브 동작이나 웹 빌드 타깃 구현을 증명하지 않는다.

로컬 후보 검증은 `python3 -B -m harness.run_tests`와 임시 `file://` Git 원본의 전체 SHA 설치로 수행한다. fixture의 v0.1.0/v0.1.1 태그는 합성 릴리스이며 실제 원격 태그가 아니다. 현재 VERSION만으로 최신 자동 추적하지 않으며 update는 명시적 ref가 필수다. 최종 후보 검사 결과는 준비서에 모으고, v0.1.0의 사후 기록은 유지한다.
