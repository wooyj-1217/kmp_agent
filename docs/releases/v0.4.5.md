# v0.4.5 지원 현황

VERSION **0.4.5**, 태그 **v0.4.5**의 제공 범위다. 직전 실제 배포 [v0.4.4](v0.4.4.md), 커밋 `42dc7f30fbb9fedf2cabcc62b8159e8125b727b8`와 비교한다. [PR #20](https://github.com/wooyj-1217/kmp_agent/pull/20)의 수정이 머지된 `6f7639bf574fd905625150f711270c7e3c03f045`를 기준으로 준비한다. 최종 배포 SHA·원격 태그 검증·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.5)에서 확인한다.

## v0.4.4 이후 수정

- 압축된 도구 출력의 원문을 읽는 `mcp__headroom__headroom_retrieve`를 명시적 읽기 capability로 지원한다. hash-only 입력을 검사하며 제품 구현 작업·정상 원장·UI fixture를 요구하지 않는다.
- 공식 `.kmp-agent/agent.py --help`와 지원 action의 단독 도움말을 제품 상태와 분리한다. 정확한 launcher 경로·원문 일치와 symlink/별칭 거부를 검사하며 임의 Python 실행은 허용하지 않는다.
- 실제 화면/입력 action만 UI 계약을 검사한다. 다른 미지원 도구는 해당 이름과 복구 경로를 포함한 오류를 반환한다. 원문 조회에 잘못된 UI 오류를 표시하지 않는다.
- 설치 프로젝트의 공식 task 명령과 `docs/guard-inputs/` JSON 예시를 맞춘다. 원장·앱 소스가 없어도 기획·문서 작업을 준비하고 필요한 사용자 결정을 질문한다. 원본 checkout용 `harness/tasks.py`는 설치 프로젝트의 명령으로 안내하지 않는다.
- `pwd; rg …` 같은 복합 셸은 계속 거부하되 조회 명령을 하나씩 실행하도록 안내한다. 인용된 정규식은 지원한다. 임의 `exec` 스크립트의 포괄 허용은 추가하지 않는다.

제품 소스 작성에는 현재 원본 기술 요구·승인 계약·단계별 검토와 ready/begin을 계속 요구한다. 정상 조회·준비의 복구를 승인 없는 앱 구현 허용으로 확대하지 않는다. [도구 조회 경계](../guard-capabilities.md), [제품 실행 계약](../product-tool-enforcement.md), [설치용 작업 명령](../task-management.md#cli와-역할-실행-범위), [단계 준비](../stage-readiness.md)를 따른다.

## 설치·전환

v0.4.3·v0.4.4 설치본은 공식 관리 경로로 게시된 v0.4.5를 명시적으로 선택한다. 태그 게시와 검증 결과를 확인한 뒤 프로젝트 루트에서 단일 명령으로 실행한다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.5
```

업데이트 전 v0.4.4의 원문 조회/help 차단이 새 버전에 의해 소급 해제되지는 않는다. 위 명령을 다른 조회·셸 연산자·`--source`/`--target`과 결합하지 않는다. 기존 source와 공식 launcher/runtime 검사를 사용하며 실제 관리 update는 신규 기획/구현 task와 분리한다. v0.4.2 이하의 첫 전환은 사용자 터미널의 새 bootstrap을 사용한다. [설치 안내](../installation.md)를 따른다.

설치 후 VERSION·선택 SHA·runtime과 재시작 안내를 확인하고 새 세션에서 훅 신뢰/활성 상태와 실제 조회·준비 경로를 재검증한다. 설치 성공·status VERIFIED는 실제 제품 인수나 훅 전달 성공이 아니다. 기존 태그·과거 원장·제품 코드/로그를 재작성하지 않는다.

## 검증 범위

기준 구현과 같은 파일의 clean checkout에서 관련 **189개 PASS**, 머지 전 핵심 **9개 재실행 PASS**가 확인됐다. 실제 설치 runtime을 사용하는 합성 fixture에서 공식 help 조회·headroom 도구 분류·준비 JSON·기획 documentation 작업의 실제 TODO 등록 성공과 계약 없는 소스 patch 거부를 확인했다. 본 버전업은 VERSION·문서만 변경하므로 이 결과는 동일 구현 파일에 한정해 재사용하고 후보의 버전/설치/관리 update/조회·guard 관련 **130개 검사 PASS**를 추가 확인했다(Python 3.13.18, rtk 1.2.0). 최종 후보 결과와 원격 태그 신규 설치·init·재설치·v0.4.4→v0.4.5 update 검증은 Release 게시 본문에 확정한다.

설치본의 실제 Codex 세션에서 신뢰된 훅을 거치는 headroom 서비스 호출·원문 복원, UI runtime, 기획부터 QA까지 실제 모델 E2E, 실제 적용 제품 업데이트·전체 인수는 **NOT_RUN**이다. 합성 hook payload 시험을 실제 세션 성공으로 표현하지 않는다. 공식 완료 인증은 보호 권한 부재로 BLOCKED이며 시험 PASS와 별도다. 원문·검증 원본은 로컬에 보존하고 공개하지 않는다.
