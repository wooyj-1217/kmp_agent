# v0.4.8 지원 현황

VERSION **0.4.8**, 태그 **v0.4.8**의 제공 범위다. 직전 실제 배포 [v0.4.7](v0.4.7.md), 커밋 `404c23f60eaf1c59a71a9779299e851fe0a89b99` 이후 [PR #27](https://github.com/wooyj-1217/kmp_agent/pull/27)의 수정이다. 준비 기준은 머지 커밋 `a4309618e043dc0aafdb3ae89a19eecaf8c95231`이며 최종 SHA·원격 태그 검증·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.8)에서 확정한다.

## v0.4.7 이후 수정과 추가

- 선택 UI가 표시 요청만 접수하고 구조화 응답을 만들지 못해도, 전체 동결 질문·선택지를 제시한 뒤 실제 사용자가 보낸 정확한 선택지 라벨을 검증한다. 앞뒤 공백·단일 불릿을 지원하고 원문은 보존한다.
- `question-status`는 UI 없이 assistant 일반 텍스트로 표시할 `text_fallback_prompt`를 제공한다. 전체 질문·Approval scope·선택지·계약 digest를 포함하며 사용자에게 선택지 하나만 답하도록 안내한다. UI item에 고정된 질문은 원래 호출에 대한 텍스트 응답만 허용하고 별도 제시가 불가능한 이유를 반환한다.
- 기존 `answer-question`·`recover-question`을 사용한다. 실제 native 질문과 인접 사용자 원문 쌍·고정 root·개설 경계·현재 계약과 파일을 검증하고, 텍스트의 전송 근거는 `text_prompt`로 따로 기록한다.
- 다른 질문의 후속 표시, 같은 native root의 다른 실행, 모호한 batch·불릿 해석, 일반 진행 요청·인용문, 원문 재사용을 차단한다. 텍스트와 UI의 중복·상충 응답은 현재 원문 끝까지 재검사하며 후속 정확한 거절이 있으면 이전 승인을 소비하지 않는다.
- 무관한 잘못된 형식의 응답·호출 중 질문을 식별할 수 없는 자료는 기존 유효 승인을 취소하는 근거로 쓰지 않는다. 식별 가능한 중복·상충은 계속 거절한다.

canonical `approve`, 동결 승인 범위·현재 bytes·명시적인 대체 체인·실패 감사는 유지한다. 자유로운 진행 요청이나 과거 비표준 ID를 승인 권한으로 승격하지 않는다. [승인·텍스트 선택 계약](../approval-authority.md#선택-ui가-응답하지-않을-때의-네이티브-텍스트-선택), [실행 정책](../execution-policy.md)을 따른다. `accepted:true`는 표시 요청 접수이며 선택 성공을 뜻하지 않는다. 이번 수정은 UI 내부의 클릭 실패 원인을 고친 것이 아니다.

## 설치·전환

신규 설치는 [설치 안내](../installation.md)의 v0.4.8 bootstrap을 명시 선택한다. v0.4.3~v0.4.7 설치본은 기존 source를 재사용하는 단일 관리 명령을 사용한다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.8
```

다른 명령·`--source`·`--target`과 결합하지 않는다. v0.4.2 이하는 사용자 터미널의 새 bootstrap으로 전환한다. 선택 SHA·runtime과 새 세션의 훅 신뢰·활성을 확인한다. 기존 원장·질문·선택지 ID는 자동 이전하지 않는다. 이전 원문이 유효하면 정확한 기존 locator/hash와 계약으로 공식 복구를 재검증하므로 새 선택을 반복 요구할 필요가 없다. 실제 제품의 설치·복구·재개는 별도 수행한다.

## 검증 범위

PR #27의 정확한 제출 커밋 `7bb6e244fe2cc4ac2decc77b2fd2302d4b6ed020` clean checkout에서 관련 **150개 PASS**, 별도 보안 검토 **40개 PASS**, 8개 변경 파일의 범위·내용 해시·상대 링크 검사 PASS를 확인했다. 임시 설치본의 새 모듈·공식 CLI·선택 SHA/clean·자체 테스트 제외도 PASS다.

실제 문제였던 기존 native 텍스트·인접 사용자 원문과 전체 질문을 변경 없이 사용해 메모리 원장 복사본에서 공식 복구·현재 유효성·기존 질문 대체 체인·멱등 검증을 확인했다. 실제 제품 원장·native 파일 해시는 전후 동일하고 실제 질문은 OPEN을 유지했다. 제품 승인·실행·인수를 수행한 결과가 아니다. 개인 원문·제품 자료·로컬 검증 로그는 공개하지 않는다.

버전·문서 후보의 영향 검사·신규 설치·init·재설치·v0.4.7→v0.4.8 update와 최종 태그/SHA·원격 검증 결과는 Release 게시 본문에서 확정한다. 실제 설치본 훅·전체 모델 E2E·공통 예제·실제 제품 업데이트/승인 복구/인수는 **NOT_RUN**이다. UI 클릭 실패의 내부 원인과 Chrome 시작 실패·RESTART_REQUIRED의 원인은 **UNKNOWN**이다. 로컬 대시보드 HTTP 검사의 샌드박스 포트 제한은 이 패치의 해결 항목이 아니다.
