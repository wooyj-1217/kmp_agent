## 0.3.0 이후 주요 변경

- 구조화 계약을 등록하면 한 foreground 호출이 기획·검토·디자인·검토·개발계획·검토·구현·독립 QA의 다음 실행을 선택한다. 인간 승인·질문·실패·중단 시 대기하거나 차단한다. 프로세스 종료 후에는 명시적 재개가 필요하다.
- 승인 원문·대상·산출물 해시를 연결하며 역할 검토, 인간 승인, QA 관찰, 공식 인증을 구분한다. 일반 PASS를 인간 승인이나 공식 인증으로 승격하지 않는다.
- 중단 복구에서 프로세스 소유권·작업공간 기준·checkpoint·통합 journal을 확인한다. [복구 계약](../recovery-contract.md).
- 작업 착수 계획·질문 정책, 사용량 연결과 맥락 검토의 opt-in 완료 점검, 지침 정비 절차를 추가했다. 정책 파일이나 문서만으로 실제 모델 호출·수집·자동 실행이 보장되지는 않는다.

## 검증 범위

병합 커밋 `2587dcd`의 기록에는 로컬 갱신 테스트 사본 기준 877 PASS·1 SKIP, 깨끗한 제출 checkout의 관련 검사 67 PASS가 보고돼 있다. 이는 과거 실행 결과이며 이번 버전의 전체 회귀 PASS로 승계하지 않는다. 신규 테스트 일부는 로컬에만 있고 배포 코드에 포함되지 않는다.

이번 버전업의 검사 결과는 [작업 기록](../work-items/2026/2026-11-10-v0.4.0.md)에 요약한다. 실제 모델의 기획→디자인→개발→QA 전체 E2E는 **NOT_RUN**이다. 설치본 새 Codex 세션·훅 활성화, 실제 적용 프로젝트 전체 검증도 미실행이다. 원격 태그 설치·update는 최종 Release의 실제 실행 결과와 구분한다.

## 사용·전환 전제

POSIX·Python 3.10+·Git·rtk·저장소 접근 권한이 필요하고 모델 실행에는 Codex 환경·권한이 추가로 필요하다. 초기 세 단계 task·기준·역할·정책·계약을 등록해야 한다. PRODUCT 실행은 계약과 단계에 필요한 native 인간 승인 근거를 요구한다.

기존 설치는 자동 갱신되지 않는다. 태그 게시 후 해당 태그 또는 최종 전체 SHA를 명시적으로 선택한다. 설치 필터를 사용하려면 선택한 0.4.0 checkout의 bootstrap을 사용한다. 기존 동결 계약·완료 이력을 새 정책으로 소급 재작성하지 않는다. 훅 신뢰·새 세션 활성화는 별도 확인하며 완전 호환이나 추가 조치 없음을 보장하지 않는다.
