# v0.4.0 — 게시 본문 원본

구조화 계약으로 기획부터 구현·독립 QA까지 foreground 연쇄 실행을 연결합니다. 승인·복구·완료 기준을 강화했으며, **실제 모델로 전체 흐름을 완주하는 E2E 검증은 아직 실행하지 않았습니다.**

## v0.3.0 대비 변경

- foreground 오케스트레이터: 등록한 작업·역할·개발계획 계약을 사용해 단계별 실행과 독립 검토를 연결합니다. 질문·승인·실패 시 대기하거나 차단하며 중단 후에는 명시적으로 재개합니다.
- 승인·완료 구분: 인간 승인 원문과 현재 대상·해시를 확인하고 구현 완료·QA 관찰 완료·공식 인증을 분리합니다.
- 복구 강화: 프로세스 소유권·작업공간 기준·checkpoint·통합 journal로 재개 가능 여부를 판단합니다.
- 운영 보강: 실행 계획·질문 정책, 응답별 사용량 연결, 구성된 완료 점검과 맥락 검토, 대시보드·지침 정비를 보강했습니다.

## 지원 범위와 제약

사전 등록된 구조화 계약을 한 foreground 호출 안에서 실행합니다. 자연어 목표의 자동 작업 분해, 상시 감시·무인 재시작, 자동 머지·배포는 제공하지 않습니다. 계약·실행 경로 테스트와 실제 모델 산출물의 품질 검증은 다릅니다.

[0.4.0 지원 범위](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.0/docs/releases/v0.4.0.md)

## 설치·업데이트

태그 게시 후 기존 설치는 제품 저장소 루트에서 다음과 같이 명시적으로 업데이트합니다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.0
rtk proxy python3 .kmp-agent/agent.py status
```

최초 설치·설치 필터는 선택한 v0.4.0 checkout의 bootstrap과 [설치 안내](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.0/docs/installation.md)를 사용합니다. 제품 파일·로그는 제품에 보관하며 기존 설치·동결 계약은 자동 변경되지 않습니다. 훅 정의를 검토·신뢰하고 새 세션에서 활성 상태를 확인해야 합니다. 모든 과거 설치 경로의 호환성을 검증한 것은 아닙니다.

## 검증·게시 상태

VERSION 0.4.0, 태그 v0.4.0. 게시 본문에는 태그의 최종 전체 SHA와 원격 설치·update 실행 결과를 대입합니다. 이번 버전업에서 임시 Git·합성 세션 기반 설치·릴리스 관련 테스트 25개와 문서 링크·diff 검사를 통과했습니다. 실제 모델 E2E, 실제 적용 프로젝트 전체 검증, 설치본 세션·훅 활성화는 미실행입니다. 최종 SHA·원격 검증·공개 링크를 대조한 게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.0)에서 확인합니다.
