# v0.2.0 후보 준비·검증 기록

## 최종 태그 준비 기록

VERSION 0.2.0 / 태그 v0.2.0. 준비 기준 원본 HEAD는 `b802d18b068d4a213946a0c7f3b5dee77b6c6621`이며 최종 커밋 식별자는 태그가 가리키는 SHA다. 자기 파일을 포함하는 미생성 SHA를 기록하지 않는다. 최종 전체 SHA·원격 설치 결과·정식 게시 여부는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.2.0)에서 확인한다.

기존 고정 후보 이후 릴리스 지침·본문 원본을 포함해 문서/manifest를 갱신했다. 코드·fixture는 기존 전체 회귀와 동일하다. 새 추가 검사 범위는 문서/태그 링크/CLI 대조, 포함 파일·민감 정보 패턴, 실제 배포 트리의 인스턴스 ID 제외 및 설치·설정 보존이다. `.kmp-agent/project.json`은 Git 추적만 해제하고 작업 원본을 보존하며 ignored 처리한다. v0.1.0 기록과 기존 로컬 검증은 보존한다.

최종 포함 목록은 manifest의 files/sha256으로 고정한다. manifest 자기 해시는 외부 스테이징/커밋 검증 기록으로 확인한다. Git 태그 게시 후 깨끗한 임시 대상에서 실제 원격 ref 설치·init을 확인하고 통과해야 Release 본문에 확인한 SHA/결과를 대입한다. 이 준비 기록 자체는 원격 검증 PASS나 게시 완료를 뜻하지 않는다. 설치본 새 Codex 세션은 별도 미실행으로 남긴다.

## 이전 로컬 후보 준비 기록 — 당시 상태 보존

### 기존 0.2.0 로컬 후보 준비 시점

> 본문 지침 추가(2026-10-20): 진행 중인 별도 배포 작업이 없음을 사용자에게 확인했다. [공통 지침·템플릿](README.md#github-release-본문)과 [v0.2.0 초안](v0.2.0-notes.md)은 기존 고정 후보 이후의 문서 변경이다. 기존 후보 SHA·payload·시험 기록은 보존하며 이 추가분에 소급 적용하지 않는다. 현재 manifest는 원래 고정 목록을 유지하고 post_freeze_documentation으로 차이를 표시한다. 최종 후보에 포함하기 전에 목록/해시를 다시 고정하고 문서·링크·명령·지원 범위 대조를 적용한다. 코드/입력이 바뀌지 않으면 기존 기능 시험은 내용 동일성 근거로 유지한다. 최종 배포 SHA·원격 설치는 여전히 미확정이며 본문은 게시 보류다.

VERSION은 **0.2.0**, 예정 태그는 **v0.2.0**이다. 원본 HEAD는 `b802d18b068d4a213946a0c7f3b5dee77b6c6621`로 유지한다. 태그/원격/Release를 만들지 않았으며 설치 가능한 원격 0.2.0 배포라고 표시하지 않는다. [0.2.0 지원 문서](v0.2.0.md)와 설치 안내를 연결했다. 아래 최초 기록의 VERSION 0.1.0·미검증 진술은 당시 상태다.

로컬 준비 완료 판정은 최종 receipt가 모두 PASS이고 고정 해시가 유지되는 경우다. 원격 게시와 게시판 설치 검증은 별도이며 아직 수행하지 않았다.

최종 후보 payload는 [manifest](candidate-manifest.json)의 files/sha256을 기준으로 한다. manifest 자체는 자기 해시를 포함하지 않고, 임시 Git snapshot 외부 receipt에 전체 해시를 보관한다. 원본/사본 차이를 고정 전후 비교하고 변경 시 해당 범위 재검증한다. 원본에는 커밋하지 않는다.

- **포함:** 공통 지침·템플릿·코드·시험·설치기·버전/지원 문서. 합성 메모 공통 예제 205파일은 변경 전후 P/D/CR, 토큰·화면·반환·캡처·검증 근거의 링크와 재현 맥락을 유지하기 위해 포함한다. 실제 제품 목표나 스택 확정은 아니다.
- **제외·보존:** `.kmp-agent/project.json`(하네스 인스턴스 고유 ID), 기존 ignored `.harness/`, `.codex/`, `.agents/`, `.serena/`, 개인 환경 문서·환경변수·캐시·로그·원본 세션. 원본에서 삭제하지 않는다. 로컬 환경은 설치 대상에서 자체 생성/보존한다.
- **개인정보 검토:** 텍스트 절대 개인 경로·이메일·키 패턴과 제품 참조를 점검했다. 시험 이메일·가짜 비밀값·마스킹 탐지 정규식은 테스트로 식별했고 실제 credential을 발견하지 않았다. 캡처 125장을 전체 축소 시트로 검토했고 합성 메모 UI이며 GPS 메타데이터가 없다. OCR은 이 환경에서 125장 모두 빈 결과여서 PASS 근거로 사용하지 않는다. 숨겨진 정보 전반의 부재를 보증하는 검사는 아니다.
- **공개 범위 정리:** 회고의 외부 제품 경로·실제 세션/메시지 대응은 로컬 원본 사본에 보존하고 배포 문서는 일반화했다. v0.1.0 기록은 수정하지 않는다. 과거 문서의 `.harness/` 링크는 로컬 전용 근거이며 배포에 원문/로그를 포함하지 않는다는 뜻이다.
- **편집 상태:** 사용자가 이번 전체 후보에도 다른 편집 세션이 없음을 확인했다. 그 답변 이후 최종 임시 사본을 고정하고 원본 해시 변동을 다시 검사한다. 새 편집 충돌/차이가 나오면 영향받는 후보 검증을 무효화한다.

공통 원본은 로컬 임시 Git 저장소에 재현하고 전체 SHA를 설치한다. 실제 v0.1.0 태그 내용 → 후보 SHA 업데이트, 실패 시 원복, init 반복, 설정·제품 ID·로그 보존, 중단 recover, 이전 SHA 명시 롤백과 후보 재적용을 실제 시험했다. 정상 install 상태가 설치본 Codex VERIFIED를 뜻한다고 처리하지 않았다. 회귀 진입점은 `rtk proxy python3 -B -m harness.run_tests`다. `discover -s harness`의 stdlib logging 이름 충돌을 피하고 모든 시험 모듈의 import 오류도 실패로 처리한다. 전체 회귀 결과·후보 SHA는 로컬 `.harness/releases/0.2.0/`의 snapshot/regression/integration 기록과 마지막 완료 보고에서 대조한다.

CLI 전체 sync는 기존 전체 변환·자동 연결을 유지하며 배치 저장기를 재사용해 반복 이벤트 로그 파싱을 제거했다. long-session 최초/재실행, 이벤트 확정 뒤 metadata 전 강제 종료/재수집, 별도 link 2회/status/probe/projects를 합성 시험한다. 훅의 기존 실행 계약·자동 확인 결과는 보존하며, 고정 후보의 변환·설치 연결 회귀로 추가 확인한다. 후보에서 실제 LLM 기획/디자인·설치본 자동 Codex·KMP 앱/웹/서버 빌드·실제 원격 게시판은 재실행하지 않는다.

## 최초 준비 기록 — 아래는 당시 상태로 보존

점검일: 2026-10-20 UTC. 현재 VERSION은 **0.1.0**, HEAD는 **b802d18b068d4a213946a0c7f3b5dee77b6c6621**, 브랜치는 main이다. 원격 main과 v0.1.0의 peeled commit도 같다. 다음 번호는 **0.2.0 / v0.2.0 제안**이며 아직 선택·수정·생성·배포하지 않았다. 새 명령·독립 역할·단계/코드 추적·순차 수집의 추가이므로 단순 패치보다 minor 후보가 적절하다. 최종 호환성 검토·사용자 선택 전에는 확정 버전으로 사용하지 않는다.

기존 [VERSION·태그 기반 릴리스 규칙](README.md)을 사용하며 별도 상태표/RC 번호 체계는 만들지 않는다. 이 문서는 로컬 준비/보류 목록이지 정식 배포 기록·기능 구현 완료 선언이 아니다. [파일별 후보 목록](candidate-manifest.json)은 이 점검에서 읽은 바이트와 분류를 남기며 배포 archive나 새 코드 버전이 아니다.

## 다른 세션·개입 분류·훅 조사

- 기존 tasks 원장에서 개입 분류·훅 타임아웃 조사에 대응하는 활성 TASK/agent_run은 확인하지 못했다. 이것은 다른 세션이 없거나 작업이 끝났다는 뜻이 아니다. 세션별 편집 파일 소유권/실시간 수정 상태는 **미확인**이다.
- 관측 가능한 별도 저장소 세션의 마지막 task_complete와 TASK-SEQUENTIAL-EVIDENCE-VALIDATION의 DONE은 순차 수집 검증 완료 근거다. 그 기록을 개입 분류·타임아웃 조사 완료로 대신하지 않는다.
- 기존 pending→원문 연결과 REQUIREMENT_CHANGE 등 수동 분류 기록은 있으며 최근 개입 연결은 03:20 UTC, 최근 수집 원문 기록은 03:25 UTC다. 별도 진행 중인 분류 작업의 결과·완료·최신 요청의 수집/분류 상태는 **미확인**이다. 자동 의미 분류기는 현재 제공하지 않는다.
- `harness/logging.py`, `harness/codex_sync.py`, `harness/cli.py`, `harness/tasks.py`, `harness/test_interventions.py`, 훅 설정 및 관련 지침은 다른 작업과 겹칠 수 있어 **수정하지 않았다**. 공유 `.harness/` 원장·원문·진단도 이 조사에서 갱신하지 않았다. 기존 지원 표/README/운영 문서도 직접 수정하지 않고 이 두 새 준비 파일만 추가한다.
- 다른 세션의 수정 범위·완료 근거가 확보된 뒤 공동 파일을 확정해야 한다. 관측 사이 해시가 같더라도 파일 소유권이나 향후 무수정을 증명하지 않는다. 자동 분류 수정이 실제 존재하는지 확인되지 않은 상태에서 후보 기능으로 올리지 않는다.

### 최초 점검 기록 — 아래 판단은 당시 상태로 보존

**최초 점검 당시 판단: 배포 차단.** 직접 타임아웃을 재현·확정했다고 쓰지는 않는다. 다만 원인 미해결인 종료 누락과 실제 한계 근접 지연이 공통 로그 신뢰성에 영향을 주므로, 자동 원문 수집·개입 연결을 포함하는 다음 배포의 준비 완료를 선언할 수 없다.

- `.codex/hooks.json`의 두 훅 timeout은 120초다. 진단에서 2026-10-20 완료 훅이 약 40.7→82.8→93.5→**116.857초**까지 증가한 기록을 확인했다.
- 같은 날 sync_started는 있으나 hook_exited가 없는 호출이 8건이다. 최근 04:31:46 UTC 호출도 04:34:45 UTC 관측 시 종료 기록이 없었다. 마지막 정상 sync metadata는 03:25:54 UTC다. 종료 코드·프로세스 생존·외부 강제 종료 원인은 미확인이므로 이 8건을 전부 타임아웃이라고 단정하지 않는다.

- 영향: 사용자 원문 수집 지연/누락 가능성, pending 개입 연결 지연, 원문/사용량을 포함한 전체 수집 주장 불가. 이미 기록된 명령/TASK 근거가 전부 소실됐다는 뜻은 아니다. 래퍼·CLI fallback도 원본 sync에 의존하므로 별도로 성능/중단/재시도 근거가 필요하다.
- 해제 조건: 조사 담당의 완료/소유권 확인, 장기 세션·증가 로그·동시 수집에서 120초 안의 실제 런타임 종료와 후처리, 정상/중단 후 재수집의 원문 정확히 한 번·개입 pending→연결·사용량 중복 방지·JSON/기록 무결성, 활성 코드와 시험 소스 일치를 확인해야 한다. 원인·허용 환경·한계를 명시하고 불명 호출은 그대로 보존한다.
