# 에이전트 흐름도 · 현재 사용자 지시의 파생 구현 기준

이 문서는 현재 사용자 지시의 구현 요약이며 사용자 원문이나 별도 승인 문서로 승격하지 않는다. 실제 원문은 세션 수집 기록이고 식별자 확인 전 UNKNOWN. 제품 요구·정책을 바꾸는 기능이 아니다.

## 화면과 범위

기존 ‘현재 작업 계획’ 영역만 HTML/SVG 흐름도로 교체한다. 새 탭·별도 진행판을 만들지 않는다. 대시보드는 프로젝트 전체를 기능/작업종류별로 구분해 보여주며 CMD는 현재 실행의 전체 Todo·하위 활동을 유지한다. 둘은 task/agent_run/criteria/validation/issues/approval/plan 참조를 공유한다. 현재 작업 완료는 프로젝트 전체 완료가 아니다.

오케스트레이터는 위쪽 조율 위치, 기획/디자인/개발/QA는 아래쪽에 배치한다. QA는 여러 단계의 검토 대상·작업을 표시한다. 개발 코디네이터 아래에는 native development_area로 실제 배정된 역할만 표시한다. 특정 플랫폼을 고정하지 않는다. 호출 요청/실제 시작/종료 후 검토/호출 실패와 품질 실패를 구별한다. 메인 세션 조율과 별도 모델 실행을 구별하며 실제 프로세스 생존은 UNKNOWN이다.

## 상태·연결·상세

필수 기준·현재 결과/입력/코드 근거를 통과한 작업만 완료 체크한다. 부분 차단을 전체 역할 차단으로 확대하지 않는다. 실제 handoff의 from_task_id/to_task_id, QA 발견의 qa_task_id/source_task_id 및 담당 역할/수정 task를 이용한다. 출처 없는 연결을 실행 인계처럼 그리지 않는다. 조율 관계는 구조 표시이고 인계/보완 선과 구별한다. 열린 QA 반환만 강조하고 해결 이력은 상세에 둔다.

노드를 선택하면 기존 상세 화면에 역할 작업 체크리스트·실행/재시도/상한·선행 조건·산출물·검증·원본 로그를 표시한다. 원본 식별자·명령·해시는 기본 노드에서 숨긴다. 대상별 build/run/qa는 명시적 target/check_kind 기준으로 따로 조회하고 공유 코드나 개발 역할 배정으로 추정하지 않는다. 미검증을 적용 제외로 바꾸지 않는다.

오래된 실행은 상태 확인 필요이며 정상/실패로 자동 확정하지 않는다. 조회 연결 실패는 마지막 성공 화면과 별도로 알린다. 갱신 시 노드 선택·펼침·스크롤을 보존하고 대상 변경을 알린다. 합성·과거는 명시한다. 단일 강조색·텍스트/아이콘·반응형 배치를 사용하고 애니메이션으로 실행을 암시하지 않는다.

## 검증

기획/디자인 QA, 병렬 전문 작업, 선행 대기, QA 반환/보완/재검증, 일부 차단, 사람 결정, 대상 미검증, 호출 실패/상한, 오래된 활동/연결 실패, 완료·과거·합성의10개 화면 사례를 재현한다. 합성 상태 시험과 실제 현재 작업 기록을 분리한다. 실제 새 모델 호출·제품 앱/DB 실행은 범위에 포함하지 않는다. 설치본·제품·DB·원격을 변경하지 않는다.
