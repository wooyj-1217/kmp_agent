# 운영 설계

아래 기준은 확정된 설계 결정이다. [최소 로거](harness-logging.md)와 [작업 관리](task-management.md)의 상태·의존성·검토·인계·역할 실행 ID·명시적 사용량 귀속을 구현했다. 독립 역할 자동 호출·전체 예산·평가 자동화는 **PLANNED**다.

## 작업 관리

프로젝트→기능→작업의 분해·배정, 담당·의존성·PR과 상태의 기준은 [작업 관리](task-management.md)다. 최소 구현과 설계만 된 필드를 구분하며 문서 계약을 새 런타임 기능으로 표현하지 않는다.

## 가정·미결정·사용자 질문

CONFIRMED / INFERRED / UNKNOWN은 요구사항의 근거 수준이다. CONFIRMED는 명시된 결정·확인 가능한 근거, INFERRED는 추론·가설, UNKNOWN은 미확인이다. 조사 사실과 사용자 제품 결정을 구분하며 근거 분류가 진행 허가나 차단 판정 자체는 아니다.
가정마다 **진행 가능 / 확인 전 차단 / UNKNOWN**, 적용 작업·단계, 제안자·근거·영향·재검토 조건을 별도로 기록한다. 진행 판단이 UNKNOWN이면 의존 작업을 임의로 진행시키지 않는다.
역할 재량 안의 가역적인 시각·기술 세부 사항은 직접 제안하고 가정·근거를 남길 수 있다. 사용자 의도·핵심 정책·제품 방향을 그 방식으로 확정하지 않는다.

불명확한 의도·핵심 정책은 기획으로 반환하고 관련 핵심 질문을 묶어서 사용자에게 요청한다. 질문에는 불분명한 점, 필요한 결정, 추천안·대안과 각 선택의 영향을 간결하게 제시한다. 기존 답변·결정 근거를 확인해 이미 답한 내용은 다시 묻지 않는다.
답변 전에는 해당 작업·단계만 차단한다. 응답 부재는 동의가 아니며, 무관한 작업은 계속할 수 있다. 이번처럼 제품을 선정하지 않는 문서 작업에는 미정 제품 정책을 대신 확정하지 않는다.
범위 밖 항목은 제외 근거·후속 작업·담당을 남긴다. 범위 판단이 미정이면 자동 제외하지 않는다. UNKNOWN 수용 기준도 완료 판정에서 일괄 삭제하지 않는다.
요구 변경 시 이유·수용 기준·영향 명세/시안·작업·담당·PR·재검토/재검증을 연결한다.

## 검증과 완료

결과는 `PASS / FAIL / NOT_RUN`이다. 환경 차단으로 미실행한 검증은 NOT_RUN과 사유를 기록한다.
필수 검증이 FAIL 또는 NOT_RUN이면 완료 선언과 DONE 전환을 허용하지 않는다. 거부된 완료 선언도 이벤트에 남긴다.
가정·미결정의 영향과 차단은 위 기준을 적용하고 Mock UI·실제 연동·UI 최종 검증 등을 구분한다.
검증 보고 제출과 제품 작업 통과는 구분한다.

기획의 고유 수용 기준 ID를 사용자 시나리오 → 디자인 명세 → 구현 → 검증 증거에 연결한다.
증거에는 기준 ID, 결과, 재현 절차, 기대·실제값, 검증한 제품 코드 커밋, 요구·디자인 명세 버전, 환경을 기록한다.
미커밋 자체 확인을 최종 제품 커밋의 증거로 대신하지 않는다. 코드·명세 변경 후 영향 범위를 새 버전으로 재검증한다.
요구·정책 문제는 기획, 디자인 문제는 디자인, 구현 오류는 개발로 반환한다.

## JSONL 로그

아래는 전체 실행기의 목표 계약이다. 현재 구현·수동 입력·미지원의 구분은 [최소 로거 상태](harness-logging.md)를 따른다. 작업 종류는 HARNESS_BUILD / HARNESS_IMPROVEMENT / PRODUCT로 구분한다.

실행기가 구조화된 JSONL 이벤트를 자동 기록한다.
`feature_id`, `task_id`, `run_id`, `agent_run_id`로 기능·작업·루프 실행·개별 에이전트 실행을 연결한다.
재시도는 개별 시도로 구분하고 이전 결과를 덮어쓰지 않는다. 모델 호출은 호출 ID로 연결한다.
사건 ID·UTC 시각·실행 내 순번·역할·종류·산출물 및 원인 참조를 기록한다.
실행 시작·종료·오류·중단, 도구 호출, 상태 변경, 인계, 검증, 재작업·재시도, 사람 개입, 완료 선언을 기록한다.
상태 변경에는 전후 상태와 근거, 완료 선언에는 증거와 허용·거부 결과를 남긴다.
사람 개입은 의도된 사용자 결정과 오류·누락 때문에 필요한 개입으로 구분한다.
비밀값을 기록하지 않는다. 마스킹·원문 보관·보존 기간은 미결정이다.

## 버전과 환경

실행마다 에이전트 정의 해시, 하네스 커밋·버전, 평가 버전, 제품 커밋, 실행 환경을 고정·기록한다.
입력·출력 산출물과 명세 버전을 연결하며 기준 변경은 새 실행으로 구분한다.
초안 작성·검토는 Git 커밋이 없어도 가능하다. 역할 간 실행 인계에서는 문서·API 계약·시안의 경로와 적용할 Git 커밋을 고정하고 해당 제품 커밋·수용 기준 ID를 검증 근거에 연결한다.
기존 하네스 문서 시험은 예외 범위와 원본/불변 스냅샷 해시를 명시해 인계했다. 이는 Git 커밋으로 표현하지 않으며 제품 실행 인계·품질 검증의 버전 요건을 만족했다고 주장하지 않는다. 새 제품 인계에서 버전 정책 예외가 필요하면 사유·범위·승인 근거를 먼저 명시한다.
변경 이력은 Git으로 관리한다. 계약 변경 시 영향 작업·담당·PR과 기준 버전 변경을 기록한다. 해시·버전 변경은 완료·검증 PASS가 아니다.
개발 결과 새 제품 커밋은 초기 입력 커밋과 구분해 기록하고 검증 실행은 실제 검증 대상 커밋을 고정한다.
미커밋 결과를 커밋된 결과로 표현하지 않는다. 해시 대상 범위·버전 형식·환경 고정 방법은 미결정이다.

## 사용량

모델 호출별 입력·출력 토큰, 제공되는 캐시·추론 세부 항목, 비용·시간을 기록한다.
도구·모델·호출 ID, 원본 필드·단위, 비용 출처 또는 가격표 기준을 보존한다.
세부 토큰이 입력·출력에 포함되면 다시 더하지 않는다. 누적 보고와 최종 보고도 중복 집계하지 않는다.
누락은 `UNKNOWN`이며 0으로 대체하지 않는다. 부분 누락 시 알려진 소계와 누락 범위를 함께 표시한다.
호출 시간과 전체 실행 경과 시간을 구분한다. 추정값은 실제값과 구분하고 방법을 기록한다.
호출 → 에이전트 실행 → 작업 → 기능으로 집계하며 실패·중단·재시도의 토큰·비용도 포함한다.
제공 필드·비용 출처·시간 측정 경계는 실행 어댑터 결정 후 확인한다.

## 개선 평가

| 지표 | 평가 내용 |
| --- | --- |
| 사람 개입 | 의도된 결정과 오류·누락 개입을 각각 집계 |
| 최초 검증 통과율 | 재작업 전 최초 검증의 필수 기준 통과 여부 |
| 자동 검증 통과율 | 대상 기능의 필수 자동 검사 목록·단위를 고정해 PASS 비율 확인; NOT_RUN·누락을 성공으로 제외하지 않음 |
| 미검증 완료 보고 | 필수 증거 없는 완료 선언; 거부된 선언 포함 |
| 자동 복구율 | 오류 대응 목적의 사람 개입 없이 실패를 복구한 비율 |
| 실패 후 복구 성공률 | 실패 후 필수 검증 PASS까지 복구한 결과; 자동·사람 도움·미해결을 구분 |
| 재작업 범위 | 반환된 역할·작업·수용 기준·변경 산출물 |
| 총 토큰·비용 | 실패·중단 포함 전체 사용량과 UNKNOWN 범위 |

하네스 변경 전후는 동일 평가 기준·평가 버전으로 비교한다.
제품·명세·환경·모델 등 비교 조건을 기록하며 효과를 확인한 뒤 채택한다.
평가 사례, 분모·측정 구간, 채택 임계값은 [미결정 사항](open-decisions.md)에 둔다.
