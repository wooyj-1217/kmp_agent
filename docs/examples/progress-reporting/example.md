# 진행 보고·조사 위임 격리 예시

합성 문서 예시이며 실제 제품 작업·사용자 승인·모델 출력이 아니다. 단일 기준은 [공통 운영 지침](../../operations.md#progress-reporting)이다.

## 시작 보고

- [ ] **입력·의존 경로 조사**
- [ ] 변경안 작성
- [ ] 검증·결과 보고

목표는 공통 지침이 새 역할 입력에 전달되는지 확인하는 것입니다. 범위가 명확한 경로 비교를 조사 에이전트에 맡기겠습니다.

## 위임 입력

- 전체 목표: 공통 보고 원칙을 새 세션·신규 역할 입력·향후 선택 버전 설치로 전달한다.
- 조사 질문/범위: AGENTS.md, docs/operations.md, harness/roles.py, harness/projects.py, bootstrap.py의 입력·설치 연결을 읽기 전용으로 조사한다.
- 제외: 제품 화면·전역 설정·CLI 복구·릴리스/설치. 파일 수정·새 모델 호출 금지.
- 기준/변경: 조사 시작 시 고정한 기준 커밋·작업 트리 상태. 기존 변경 보존.
- 반환 형식: 결론 / 최소 근거 위치(path:line) / 미확인 사항. 원본 출력 덤프 금지. 미지원 호출을 실제 수행으로 표현하지 않는다.

## 조사 결과 반환

- 결론: context의 definitions에 운영 지침이 포함되어 신규 입력으로 전달된다. 기존 동결 입력은 소급 갱신되지 않는다.
- 근거 위치: harness/roles.py의 Roles.prepare/context (기존 context 재사용과 운영 지침 원문·해시 전달).
- 미확인 사항: 새 모델의 실제 보고 준수는 호출하지 않아 NOT_RUN이다.

위 결과는 손으로 작성한 형식 예시이며 독립 모델 출력이 아니다.

## 단계 전환 보고

- [x] 입력·의존 경로 조사
- [ ] **변경안 작성**
- [ ] 검증·결과 보고

새 입력은 기존 경로를 사용할 수 있습니다. 공통 운영 지침에 원칙을 정의하고 진입 문서에서 참조하겠습니다.

## 오류 보고

조사 도구가 없어 일부 검색을 실행하지 못했습니다(원인). 근거 위치 확인이 남아 있습니다(영향). 직접 파일을 확인해 보완하겠습니다(다음 조치). 실제 위임을 수행한 것으로 기록하지 않겠습니다.

## 종료 보고

- [x] 입력·의존 경로 조사
- [x] 변경안 작성
- [x] 검증·결과 보고

공통 지침 참조와 신규 컨텍스트 전달을 확인했습니다. 근거는 해당 작업의 로컬 검증 기록에 보존합니다. 모델 준수 시험·배포/설치 적용은 NOT_RUN입니다.
