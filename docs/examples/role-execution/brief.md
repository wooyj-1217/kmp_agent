# 메모 예제 실행 시험 입력

기존 ../task-handoff/requirements.md의 미승인 메모 가설과 UNKNOWN 정책을 보존한다. 실제 제품·MVP 선택이 아니다. 이번 사용자 요청으로 허용된 하네스 시험 범위에서만 비어 있지 않은 본문의 입력·가상 저장·성공·실패·재시도를 한 화면으로 만든다. 실제 저장, 빈 값·길이·이탈·처리 중 편집 정책 채택은 제외한다.

목표는 별도 프로세스의 planning→design→실제 브라우저 검증→명시적 CR→새 작업 재실행과 P/D/개발 인계 버전 연결이다. 입력·산출물은 기존 작업 기록과 불변 스냅샷으로 연결한다. 기획은 화면별 기능·행동·예외, REQ/POL/AC, 근거·미결정 차단을 전달한다. 디자인은 실제 tokens.css, components.html, system.md, 대표 A/B 시안과 단일 대상 화면 전체를 생성한다.

대표 방향 A 선택은 대기·재개 시험에 쓰는 **합성 시험 결정**이다. 실제 사용자 선택이 아니다. 실제 제품 작업은 대표 시안을 보여준 뒤 사용자 결정을 받아야 한다. 실행 어댑터가 fixture라면 생성기는 결정적 로컬 프로그램이며 LLM 실행으로 보고하지 않는다.

필수 검증: SCREEN-001의 EMPTY/EDITING/SAVING/SAVED/ERROR를 390×844/1280×900에서 렌더링, 긴 본문과 오류를 포함한 캡처 시각 검토, 입력·가상 저장·오류 본문 유지·재시도·키보드/포커스. 구조·동작·시각 판정은 분리하고 실행하지 않은 항목은 NOT_RUN. 실제 제품 검증은 별도다.
