# 명시적 변경 시험 — CR-001

합성 시험 요청: 현재 D-001의 가상 저장 성공 안내 첫 문장 `가상 성공입니다.`를 `메모가 저장됐어요`로 바꾼다. 뒤의 실제 저장·영속성을 보장하지 않는 안내는 유지한다. 실제 사용자 정책 승인이나 제품 변경이 아니다.

REQ-002 / EX-FEAT-001-AC-002, SCREEN-001/SAVED, 완료 피드백 컴포넌트 예제와 A/B/활성 화면, 성공 문구 검사·긴 문자열 캡처가 영향 범위다. 기획과 디자인에서 해당 범위만 갱신한다. 다른 REQ·상태·토큰·컴포넌트 구조·업무 정책·기존 P/D 기준본은 유지한다. 새 P→D→검토→개발 인계 버전을 연결한다. 자동 감지 대신 명시적 재실행을 시험한다.

대표 A/B에는 성공 상태가 없으므로 bytes를 유지한다. 디자인은 원래 A/B·tokens.css·components.html·A-final revision1·components-final.html을 덮어쓰지 않고 새 성공 문구를 반영한 최종 화면/컴포넌트 파일을 추가하고 현재 index·design·system의 기준 참조만 함께 갱신한다. 실제 생성기는 이전 입력 원문을 재사용하며 변경 없는 파일은 reuse로 지정할 수 있다. 상단 혼용 표기 `選択 A`는 새 최종 화면에서 `선택 A`로 고치는 가역적 디자인 번역 개선으로 기록한다. 이전 캡처/파일의 원문은 보존한다. 새 선택 질문은 하지 않고 기존 합성 A 결정을 재사용한다.
