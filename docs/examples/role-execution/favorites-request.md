# CR-002 — 즐겨찾기 구조 변경·역할 연결 시험

사용자의 하네스 연결 검증 요청에 따른 **시험용 합성 정책**이다. 실제 제품·MVP·사용자 승인으로 승격하지 않는다. 기존 메모 가설·UNKNOWN 정책은 유지한다. KMP 참조 구조는 이 예제의 개발 계획 연습에만 채택하며 앱 구현·빌드는 하지 않는다.

합성 정책: 메모 기본 즐겨찾기=false. 목록과 편집 화면에서 누르면 즉시 반전한다. 목록은 선택/미선택을 아이콘·텍스트와 aria-pressed로 구분한다. 즐겨찾기 먼저, 각 그룹 안에서는 원래 생성 순서(동률이면 ID 오름차순)를 유지한다. 해제하면 원래 순서로 복귀한다. 같은 메모를 목록↔편집으로 이동해도 값이 유지돼야 한다. 샘플 메모 3개와 빈 목록 검토가 가능해야 한다. 상태는 현재 페이지 메모리에만 존재하며 새로고침 영속성·API·실제 저장은 범위 밖이다. 기존 가상 저장 성공/실패/재시도와 기존 미정 정책을 유지한다.

기획은 새 REQ/POL/AC와 목록·편집 간 흐름, 기본/선택/해제/빈 목록·예외를 정의한다. 중요 사항은 표·흐름 도식으로 연결한다. 확인 가능한 출처와 가설·UNKNOWN을 구분한다.

디자인은 **현재** prototype/index.html에 연결할 단일 HTML 앱(목록/편집 라우트), 실제 공유 토큰·즐겨찾기 컴포넌트·상태 갤러리와 system/design 명세를 갱신한다. 소스 검사를 위해 모든 즐겨찾기 토글은 `data-action-id="ACT-FAV-TOGGLE"`, 메모 식별자는 `data-memo-id`, 목록은 `data-screen-id="SCREEN-LIST"`, 편집은 `data-screen-id="SCREEN-EDITOR"`로 명시한다. 라벨/역할은 실제 접근 가능하게 만든다. 목록 메모를 여는 버튼과 토글 버튼을 구분한다. 개발자가 판단할 수 있는 필수 상태·토큰/컴포넌트 규칙을 작성한다.

제품 화면과 현재 컴포넌트 갤러리에는 하네스 검증/NOT_RUN/PASS/작업·버전/실행 횟수 문구를 넣지 않는다. 가상 저장·샘플 초기화·빈 목록 같은 검토 장치는 제품 영역과 구분하되 하네스 검증 상태는 표시하지 않는다. 해당 상태의 공식 원본은 기존 검증 기록이다. 과거 P/D snapshot과 옛 파일은 수정하지 않는다. 새 화면·스타일은 새 파일로 만들고 현재 고정 경로 index/components/system/design은 필요한 부분만 갱신한다. 제출 시 보관에 필요한 모든 간접 파일도 reuse 또는 files로 포함한다.

검토자는 상위 Codex다. 실제 문제는 관측한 그대로 기록한다. 결함이 없으면 별도 복제 후보에 토글을 숨기는 합성 결함을 넣어 반환·수정·재렌더링 경로를 검증할 수 있다. 그 경우 **합성 시험용 결함**임을 issue와 보고서에 명시한다. 디자인 에이전트가 스스로 브라우저/캡처를 봤다고 주장하지 않는다.

개발 에이전트는 승인된 정확한 P/D·토큰·컴포넌트·시안·AC·검토기록·KMP/Clean Architecture 지침을 실제로 읽고 입력 확인과 구현 계획만 작성한다. 현재 저장소에는 .kt/.kts 앱 모듈이 없으므로 제안 위치를 기존 코드처럼 표현하지 않는다. 실제 구현·KMP 빌드·플랫폼 검증은 후속 NOT_RUN이다.
