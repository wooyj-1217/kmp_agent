# 상위 검토자의 디자인 수정 재개 결정

사용자 선택·제품 승인으로 취급하지 않는 검토 흐름의 진행 결정이다. TASK-STAR-RETURN의 기존 활성 실행/두 번째 시도를 재개한다. max_attempts=2를 늘리지 않는다. 최초 fixture 생성 실패와 다음 checkpoint의 전체 초안/원본은 보존한다.

ISSUE-002: 실제 갤러리 title이 일본어로 남았다. 한국어 본문·lang=ko에 맞는 title로 수정한다. 비차단 자연 결함이다.

ISSUE-003: 실제 세 타깃에서 즐겨찾기 선택 후 빈 목록 또는 샘플 초기화를 하면 과거 메모의 선택 안내가 listStatus에 남는다. 빈 목록/초기화 때 이전 상태 안내를 지우거나 현재 상태로 갱신한다. 관련 공유 JS의 샘플 제어·상태 안내만 수정하고 저장·정렬·메모 데이터 규칙은 유지한다. 비차단 자연 결함이다.

ISSUE-004: checkpoint의 별도 합성 앱 후보는 CSS로 토글을 숨겼다. 자연 결함으로 표현하지 않는다. 정상 앱을 현재 진입 대상으로 복원하거나 숨김 스타일 없는 새 수정 시안으로 교체한다. 이전 정상/합성 후보·snapshot을 보존한다. 수정본은 앱 목록·편집에서 토글이 실제 보여야 한다. 필요한 경우 새 앱 파일/공유 JS 파일을 만들어 과거 의존 bytes를 유지한다.

P-004와 app/web-mobile/web-desktop 타깃 계약·즐겨찾기 합성 정책·기존 UNKNOWN은 변경하지 않는다. requirements.md는 소유 범위 밖이다. 새 D에는 전체 앱·웹·토큰·현재 갤러리·명세/시안/간접 자원을 files 또는 reuse로 함께 제출한다. target_artifacts에 실제 현재 entry와 REQ/화면을 기록한다. 변하지 않는 데이터·이벤트 로직·웹 배치를 재작성하지 않는다. 현재 제품 UI에 하네스 검증 상태를 넣지 않는다.

수정 에이전트는 해결을 선언해 이슈 상태를 닫지 않는다. 제출은 검토 요청이며, 상위 Codex가 실제 렌더링·조작·캡처를 다시 확인하고 resolve-issue 및 공식 검토 기록에 연결해야 개발 인계가 가능하다. 앱 네이티브·KMP 구현/빌드는 여전히 NOT_RUN이다.
