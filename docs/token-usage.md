# 토큰 기록·귀속·조회 계약

현재 코드의 추가 동작은 아래 '등록된 문맥의 자동 후속 수집'을 따른다. 과거 버전·시험 설명은 당시 기록이며 현재 프로젝트의 설치 버전·실제 연결 상태를 대신하지 않는다.

## 등록된 문맥의 자동 후속 수집

메인 기본 수행·필요 시 위임 방식에서도 사용량은 실행별로 명시 등록한다. 선택 진입점의 `usage-register`/`usage-poll`과 [완료 점검](completion-checks.md)을 사용하면 등록 누락을 필수 PASS 이전에 확인할 수 있다.

native 세션의 고유 ID는 `session_meta.id`를 우선한다. 자식 메타데이터의 `session_id`는 부모를 가리킬 수 있으므로 두 값이 다를 때 부모 ID를 자식 ID로 사용하지 않는다. id가 없는 이전 형식은 session_id를 호환 경로로 사용한다.

hook/full sync는 **명시 등록된 해당 세션 문맥만** 후속 poll하여 사용량을 연결한다. 다른 등록 세션의 수집 상태는 보존한다. 원본 응답 하나는 native 세션 ID와 response ID로 한 번만 계산하고, 미등록 문맥·복수 귀속·수치 충돌을 임의로 합치거나 0으로 바꾸지 않는다. 이미 과거에 잘못 연결된 이벤트는 이 수정으로 재작성하지 않는다.

완료 점검을 구성하지 않은 과거 작업에는 새 차단을 소급하지 않는다. 새 작업의 등록과 게이트 구성은 수행자의 책임이며 자동 모델 생성이나 모든 세션의 발견을 구현한 것으로 표현하지 않는다.

범위: 미릴리스 하네스 개발본의 수집·분류·집계·기존 흐름도 옆 토큰 조회. 실시간(Main)/작업 이력/토큰 사용 내역의 3개 메뉴 개편은 대기한다. 제품 앱·DB·설치본·원본 로그·기존 검증 판정을 변경하지 않는다.

## 버전과 과거 기록

설치본은 원격 v0.2.0, 커밋 `0e2a2468304a610ca6aa4e0b8fa6ff4bf4ebee55`이다. 개발본도 같은 기반 커밋과 VERSION 문자열을 갖지만 미커밋 서브에이전트 기능이 추가된 상태다. 새 릴리스 번호는 정하지 않았다.

기존 데모앱 제품 작업은 수정 전 설치본의 기록이다. memo-real-20261027 및 두 memo-review 기록은 에이전트 개발·격리 시험이며 데모앱 제품 작업이 아니다. 과거 이벤트의 버전을 현재 설치 정보로 교체하지 않는다. 모델 사용량을 나중에 가져온 수집기의 버전도 당시 실행의 버전으로 사용하지 않는다.

실행 출처는 해당 agent_run_started 이벤트의 정체성과 원래 실행 근거로만 표시한다. dirty 커밋만 있고 당시 코드 지문이 없으면 정확한 코드 상태는 미확인이다. 새로 기록하는 실행에는 VERSION 원문·Git 커밋/dirty·소스 지문을 함께 남긴다. 이 지문은 코드 근거이며 릴리스 인증이 아니다. 버전 문자열에서 기능을 추론하는 지원표는 없다.

역할은 독립 실행 여부와 별개다. 독립 실행은 같은 호출 ID의 실제 시작과 종료의 네이티브 스레드(또는 실행 중 수집 등록), 해당 세션 사용량 연결이 일치해야 확인한다. 메인 직접 수행은 명시적 네이티브 turn/response 컨텍스트가 필요하다. 실행 모드만 선언돼 있으면 실제 주체는 확인 불가다. 역사적 개발 부모/하위 관계는 당시 시작 전에 기록된 관계만 복구한다.

## 서로 더하지 않는 분류 축

- 작업: project_id/task_id/execution_id와 부모 ID. 이름은 표시용이다.
- 역할: 기존 orchestrator/planning/design/development/verification 등을 재사용한다.
- 개발 담당: 기존 위임 계약의 coordinator 및 선택 영역을 사용한다. 플랫폼을 필수로 추가하지 않는다. 비개발 역할은 해당 없음이다.
- 실행 주체: main_session / independent_agent / unknown. 메인이 수행해도 명시적 역할이 개발이면 개발이다.
- 실행 목적: 아래 표. 역할과 별도 축이다.
- 반복 관계: initial / review_rework / execution_retry / retest / unknown. 원인 실행·결함·대상·명시적 근거가 필요하다.

역할 설정·QA 구성·수정 대상 등 구조화된 근거만 역사적 보정에 사용한다. 당시 qa_configured 이벤트에 누락된 repair_task_id는 stage/target이 동일한 원장의 명시적 관계로만 보완하며, 독립 호출 근거로 사용하지 않는다. 이후 추가된 QA 단계·부모 관계를 과거에 소급하지 않는다.

## 수집과 집계

실행 시작 시 usage_context를 고정하고 서브에이전트 입력에 전달한다. 자동 수집은 호출 ID·스레드 ID·응답 사용량·시간이고, 작업/역할/개발 담당/목적·반복 원인은 수행자가 명시적으로 등록한다. 메인은 begin-main/register-main으로 정확한 turn 또는 response ID를 등록한다. 병렬 실행마다 별도 컨텍스트를 쓰며 전역 현재 역할이나 시간 근접 추측을 사용하지 않는다. 한 응답에 둘 이상의 컨텍스트가 겹치면 임의 비율로 나누지 않고 미연결·매핑 문제로 보존한다.

네이티브 (session_id, response_id) 하나를 한 번만 센다. 응답별 증분만 합산하며 thread/turn 누적 스냅샷과 재수집을 더하지 않는다. 부모 직접량은 하위량을 포함하지 않고, 하위 포함 합계는 응답 집합의 합집합이다. 역할별/목적별/반복별 합계는 같은 총량을 다른 축으로 보는 값이다.

OpenAI Responses의 입력 상세는 입력 토큰의 분해, 추론 상세는 출력 토큰의 분해다. 따라서 총량은 input + output이며 캐시·추론을 다시 더하지 않는다. 일반 입력은 input - cached이다. cache-write·reasoning 등 제공되지 않은 상세값은 추정하지 않는다. 공급자 설명: https://developers.openai.com/api/reference/resources/responses/methods/retrieve . 조회한 공식 문서의 지문과 발췌는 제품 저장소 token-label-implementation-20261028/provider-definition.json에 보관한다.

확인 가능한 미연결/미분류 사용량은 총량에 포함한다. 수치가 충돌하거나 원본 필드가 유효하지 않은 기록은 금액 미확정으로 격리하고 조용히 0으로 만들지 않는다. 응답이 없는 실행의 값도 미수집이며 0이 아니다.

## 보정과 화면

classifications.jsonl은 근거·방식 버전·컨텍스트·내용 ID를 가진 추가 전용 보정 계층이다. 원본 tasks/events 및 과거 보정은 유지한다. 동일 근거 재실행은 추가 0건이며 총량이 변하지 않는다. 검증 가능한 보정만 읽고 근거가 어긋나면 매핑 오류를 드러낸다.

현재 화면은 종료된 기록을 현재 실행으로 대체하지 않는다. 신규 스트리밍 경로는 실제 CLI의 thread.started와 네이티브 응답별 사용량을 실행 중 연결할 수 있다. 응답이 완료되어 원본 사용량이 기록된 뒤 보이는 방식이며 추론 도중의 연속 토큰 계수기가 아니다. 등록만 있고 원본 확인 전이면 수집 연결 확인 중이다. 과거 세 시험은 실제로 종료 후 수집됐으므로 종료 후 반영으로 표시한다. 새 실행이 실행 중에 실제로 수집됐다는 관측은 보존하여, 실행 종료 뒤에도 응답별 수집 기록으로 구분한다. 프로세스 종료 또는 네이티브 turn 종료는 작업 완료를 변경하지 않으면서 현재 실행 조회에서 제외한다. 마지막 수집 시각은 원본 사용량을 가져온 시각이고, 확인만 한 poll 시각과 분리한다. 최초 사용량 연결과 상태 파일 발행 사이에도 실행 중 반영이 종료 후 반영으로 오표시되지 않도록 확인한다.

기존 흐름도·노드 선택 하단 상세를 유지한다. 역할·개발 담당·목적·보완 및 원본 추적은 같은 읽기 모델을 사용한다. 내부 ID·지문·전체 근거는 펼침 안에 둔다. 실제 기록 화면은 에이전트 개발 시험임을 표시하며 합성 미리보기와 분리한다. 실시간 갱신은 작업/노드 선택·펼침·스크롤을 유지한다.

기존 실제 기록 검증과 새 수집 경로 검증은 별개다. 새 모델 호출 없이 격리된 OS 프로세스가 네이티브 형식을 쓰는 합성 시험으로 실행 중 연결을 검증했다. 이 결과를 새 에이전트로 데모앱 제품을 수정했다는 근거로 사용하지 않는다.
