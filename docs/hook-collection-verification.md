# 증분 훅 수집 구현·로컬 검증 — 2026-10-20

범위는 kmp_agent 수집 경로 수정·합성 시험·기존 세션의 명시적 복구다. 커밋·태그·푸시·배포·demo_app 변경은 하지 않았다. 사용자가 다른 편집 세션 없음을 확인한 후 기존 변경을 보존해 수정했다. 운영 방법과 저장 계약은 [훅 수집 운영](hook-collection.md)을 참조한다.

## 구현

- `incremental_sync.py`: 기존 Logger.sync 변환기를 I/O 없는 수집 어댑터로 재사용한다. 기존 이벤트 키·형식·순번·마스킹을 유지하고 중복 확인은 배치로 처리한다.
- 세션 잠금, 체크섬이 있는 원자적 커서, 파일 식별자·이전 바이트 해시·줄 경계 검증, 부분 마지막 줄 보류, 교체/축소/커서 손상 시 안전한 재수집을 구현했다.
- 배치 의도 저장 → 이벤트 fsync → 커서 fsync/원자 교체 순서다. 배치 쓰기 도중 중단도 로그를 자르지 않고 미기록 접미부를 완성한다. 알 수 없는 기존 손상은 보존한 채 차단한다.
- `codex_sync.py`와 설치 명령 래퍼의 hook 경로를 연결했다. 감독 프로세스가 수집 프로세스의 실제 종료와 완료 응답을 확인한 뒤 종료 마커를 남긴다. 외부 훅 제한 120초는 유지했다.
- `collection_maintenance.py`에 전체 probe·개입 연결·집계·프로젝트 검사를 분리했다. 프로젝트 확인은 승인 manifest 캐시와 실제 실행 스크립트 해시를 명시적 fingerprint 결과에 대조한다.
- 긴 공백 없는 문자열에서 발견한 URL 마스킹 정규식의 반복 탐색 비용도 줄였다. 기존 URI 마스킹 결과와 긴 비밀값 없는 문자열 보존을 시험했다. 기존 logging.py의 다른 미커밋 변경은 유지했다.

## 실행 근거

아래 시간은 이 Mac의 로컬 관측값이며 성능 상한 보장이 아니다. 수집기 시간과 프로세스 전체 시간을 구분한다. 합성 테스트는 실제 적용 프로젝트의 자동 훅 실행을 뜻하지 않는다.

## 운영 세션의 별도 복구

직전 실패 Stop invocation `bcf33180-c7f6-44c7-8082-6be1faa2d3c1`의 당시 25,138,689바이트 구간에서 기존 수집 대상 키를 다시 계산했다. 복구 전 미수집 243건을 확인하고, 원본 내용은 출력하지 않았다.

- 첫 `--mode recovery --full`: 신규 **536건** 저장, 기존 **2,085건** 중복 제외. 신규에는 기존 243건과 조사 이후 기록 293건이 포함된다. 수집기 **0.821초**, OS 프로세스 전체 **1.242초**, 종료 코드 0.
- 최종 커서 규격으로 명시적 재실행: 수집기 **0.674초**, 프로세스 **1.089초**, 이후 추가 기록 38건 저장. 커서 체크섬 도입 전 메타데이터는 안전한 전체 재수집으로 이행했다.
- 바로 이어진 수동 무변경 실행: 수집기 **0.363초**, 프로세스 **0.796초**, 신규 저장 0건. 기존 26.33MB 해시 확인은 0.093초이며 이전 JSON을 재해석하지 않았다.
- 기존 미수집 **243개 키 모두 정확히 1회**, 남은 해당 키 0건, 전체 중복 source_key 0건.
- 복구 전 events.jsonl 전체 바이트가 복구 후 로그의 동일한 접두부로 유지된다. 당시 원본 구간 해시도 동일하다. 기존 원본·이벤트·과거 진단 기록은 수정/삭제하지 않았다.

로컬 근거는 `.harness/logs/recovery-evidence/2026-10-20-hook-incremental/`에 보관한다. `before-events.jsonl`은 권한 제한한 복구 전 로그 사본, `baseline.json`은 미수집 키와 해시, `verification.json`과 `final-replay-receipts.json`은 대조 결과·종료 코드·시간이다. 일반 훅의 hook-diagnostics와 별도 collection-diagnostics에 recovery/manual 모드로 기록했다. 원문 사본을 배포 문서에 복제하지 않는다.

## 남은 확인과 제약

- 이 응답 종료 이후 실제 Codex Stop/UserPromptSubmit 자동 호출의 종료·시간은 아직 미확인이다. 직접 호출·수동 복구를 자동 훅 성공으로 대체하지 않는다.
- 원본 무결성 확인은 이전 바이트 전체 해시를 읽고, 배치 중복 확인은 이벤트 로그를 한 번 읽는다. 파일 크기에 비례하는 비용과 신규 문장 마스킹 비용은 남는다.
- 종료 마커가 없으면 UNKNOWN이다. 마지막 잠금 owner 메타데이터는 현재 생존/소유 증명이 아니며, 구형 writer에는 owner 정보가 없을 수 있다.
- 기존 ordinal/content-hash 식별자의 제약과 기존 명시적 CLI 전체 sync 경로는 유지한다. 자동 의미 분류·상시 처리·외부 서비스는 추가하지 않았다.
