# 작업 기록

[산출물 관리 규칙](../artifact-policy.md)에 따라 이유와 결정, 결과와 근거를 보관한다. 현재 작업의 명세·맥락은 해당 기준 문서에서 읽고, 관련 과거 작업만 찾아본다.

## 작성

- [템플릿](TEMPLATE.md)을 `docs/work-items/YYYY/YYYY-MM-DD-주제.md`로 복사한다. 연도·날짜는 작업 시작 기준이다. 파일명은 검색용 이름이며 하네스 작업 ID가 아니다.
- 작업 하나당 기록 하나를 사용한다. 진행 중 같은 파일을 갱신하고 종료 시 결과를 확정한다. 재개는 해당 기록을 사용하며 독립 후속 변경은 새 기록에서 이전 기록을 연결한다.
- 실제 작업 ID가 있으면 적고, 없거나 확인하지 못했으면 `UNKNOWN`으로 둔다. ID를 임의로 만들지 않는다. 관련 기능은 일관된 용어로 적어 검색할 수 있게 한다.
- 단순 오타·기계적 변경은 커밋 메시지와 실제 검증 설명만으로 충분하면 별도 기록을 생략할 수 있다. 의미 있는 기능·정책·계약·구조 변경은 기록한다.

## 찾기

저장소 루트에서 필요한 기능·작업 ID·결정 용어로 좁혀 찾는다.

```sh
rtk proxy rg -n '기능:.*동기화|<실제 작업 ID>' docs/work-items
rtk proxy rg -n '대체|충돌 정책' docs/work-items
rtk proxy git log --all --oneline --grep='<실제 작업 ID 또는 검색어>'
rtk proxy git log --follow -- docs/work-items/YYYY/YYYY-MM-DD-주제.md
```

검색 예시의 자리표시는 실제 값으로 바꾼다. 과거 코드는 기록에 연결된 커밋 또는 관련 경로의 Git 이력으로 확인한다. 현재 맥락 → 관련 작업 기록 → 필요한 원본 순서로 읽으며 매 작업마다 전체 기록을 로드하지 않는다. 이 README에 작업 목록을 수동으로 누적하지 않는다.
