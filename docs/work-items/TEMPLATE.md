# 작업 제목

- 시작일: YYYY-MM-DD
- 상태: 진행 중 / 답변 대기 / 중단 / 완료
- 기능: 검색에 사용할 관련 기능명
- 실제 작업 ID: UNKNOWN
- 실제 실행/원문 ID: UNKNOWN
- 기준 커밋: UNKNOWN
- 시작 작업 트리: 관련 기존 변경과 이번 소유 범위

## 요청과 범위

요청 요지와 실제 근거 경로. 변경 목표, 영향받는 요구·화면·데이터/API 계약, 유지할 동작을 짧게 적는다.

## 결정과 이유

- 구분: 사용자 확정 / 에이전트 제안 / 구현 사실
- 결정·이유·근거:
- 대체하는 이전 결정: 해당 기록 경로·절 또는 커밋. 없으면 해당 없음.

## 결과와 현재 기준

구현·문서 변경 요약과 현재 기준 문서 경로. 현재 상태·남은 문제·다음 행동을 적고, 미완료면 차단 이유와 재개 지점을 남긴다.

## 검증과 변경 연결

- 실제 검증 대상: 커밋 또는 작업 트리 지문·상태, 관련 명세 버전
- 수행 검사·결과·중요 미실행 범위:
- 검증 원본 경로와 환경·명령 근거:
- 알려진 관련 커밋: UNKNOWN
- 에이전트 수정 시 관련 PR·반영 릴리스: UNKNOWN (미확정이면 증거 보존)
- 증거 상태: 로컬 보존. PR에는 검증 명령·결과 요약만 기재하고 원본은 업로드·삭제·이동하지 않는다. 과거 로컬 증거 미확인은 그 사실과 현재 검증을 구분해 기록.
- 맥락 정리 결과·메인 검토 근거: UNKNOWN

없는 SHA·ID·승인·검증 결과를 채워 넣지 않는다. 커밋 전 검사와 커밋 후 검사를 구분한다. 최종 연결 커밋은 이 파일의 Git 이력에서도 찾을 수 있다.

## 종료 후 정정·후속 연결

해당 없으면 이 절을 비워 둔다. 종료 후 정정은 날짜·대상·이유·근거를 덧붙이며 과거 판정을 지우거나 새 판정으로 바꾸지 않는다.
